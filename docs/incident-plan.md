# 안전사고 모듈 — 법 분석과 설계 제안 (2026-09-23)

기존 설계(v5.4 §11, 스키마 v5.5 §10)는 "사고를 기록하고 재발방지대책을 적는다" 에서
끝난다. 법이 사업주에게 요구하는 건 기록이 아니라 **사고 뒤 기한 안에 해야 할 일**이고,
감독·수사가 보는 것도 그것이다. 그래서 사고를 "기록" 이 아니라 **"사고 뒤 할 일 목록"**
으로 만든다.

## 1. 법이 요구하는 것

| 언제 | 무엇 | 근거 | 기한 |
|---|---|---|---|
| 모든 사고 직후 | 작업 중지, 근로자 대피, 위험요인 제거, 구호 | 산안법 54조 1항, 중처법 시행령 4조 8호(대응 매뉴얼) | 즉시 |
| 중대재해 (사망 1명↑ / 3개월↑ 요양 부상자 동시 2명↑ / 부상·직업성질병 동시 10명↑) | 노동부에 발생 개요·피해 상황·조치·전망 보고 (전화·팩스) | 산안법 54조 2항, 시행규칙 3조·67조 | 지체 없이 |
| 사망 또는 휴업 3일↑ 부상·질병 | 산업재해조사표(별지 30호) 제출, 근로자대표 확인 | 산안법 57조 3항, 시행규칙 73조 | 발생일부터 1개월 |
| 모든 산업재해 | 발생 원인 등 기록·보존: 사업장·재해자, 일시·장소, 원인·과정, 재발방지 계획 | 산안법 57조 2항, 시행규칙 72조 | 3년 보존 |
| 모든 산업재해 | 은폐 금지 | 산안법 57조 1항 (형사처벌) | — |
| 사고·아차사고 뒤 | 수시 위험성평가, 감소대책, 근로자 공유 | 위험성평가 고시 15조 | 지체 없이 |
| 중처법 적용 회사(5인↑) | 중대산업재해 대응 매뉴얼 마련, 이행 여부 반기 1회 점검 | 중처법 시행령 4조 8호 | 반기 |
| 중처법 적용 회사 | 위험요인 확인·개선 절차 이행 점검 (사고 뒤 재확인 포함) | 중처법 시행령 4조 3호 | 반기 |
| 중대산업재해 (사망 1명↑ / 동일 사고 6개월↑ 치료 2명↑ / 동일 유해요인 직업성질병 1년 내 3명↑) | 경영책임자 안전보건교육 이수 | 중처법 8조 | 통지 뒤 |

산재보험 요양급여 신청은 근로자가 근로복지공단에 직접 한다(사업주 확인 불필요). 근로
기준법 재해보상(78조~)은 산재보험 미적용 시에만 — 우리 고객은 당연가입이라 화면에서
다루지 않는다. 중처법은 2024-01-27 부터 5인 이상 전면 적용: `UNDER_5` 만 제외.

## 2. 우리 시스템 분석

**이미 있는 것**
- 지시서·표준서·위험성평가 회차·조치 이행·추가 대책 — 사고 뒤 수시평가를 붙일 자리
- 안전회의(주간) 수집 항목에 `INCIDENT` 자리 (`safety_meeting_items.source_type`)
- 첨부 대상에 `incident` 예약 (`attachments.ts`, "아직 지원하지 않습니다")
- 장소 마스터(`work_locations`), 구성원, 푸시(`pushToCompany`), 감사 로그
- 경영책임자 반기 점검 카드(`assessment_reviews`), 실시규정(`risk_assessment_policy`)
- 사전조사 안전보건정보에 "재해·아차사고 이력" 글칸 (사고 기록에서 자동으로 채울 수 있다)

**없는 것**
- 사고 테이블, 작업자가 현장에서 신고하는 길, 기한 관리, 조사표 출력, 대응 매뉴얼

## 3. 제안

### 3-1. 개념
- 사고는 두 갈래: **아차사고**(다친 사람 없음) / **재해**(부상·질병·사망).
- 등급은 입력에서 자동 판정: 재해자 수, 사망 여부, 예상 휴업일, 예상 요양·치료 기간.
  - 아차사고 → 경미(휴업 3일 미만) → **보고 대상**(사망 또는 휴업 3일↑) → **중대재해**(산안법)
  - 중처법 적용 회사면 **중대산업재해** 표시를 따로 (6개월↑ 치료 2명 등).
- 등급이 정해지면 **해야 할 일 목록**이 기한과 함께 자동으로 생긴다. 사고 상세의 맨
  위는 이 목록이다.

### 3-2. 화면
- **목록 `/incidents`**: 숫자 셋(올해 재해·아차사고·처리 중 의무) → 기한 임박·지난
  의무 → 탭 전체·처리 중·종결. 목록 열: 일시·장소·요약·등급·남은 의무.
- **등록 `/incidents/new`**: 한 장, 구간 칩(헌법 1-6).
  1. 무슨 일 — 아차사고/재해 단추, 일시, 장소(마스터 + 상세), 지시서 연결(선택, 사본
     복사), 발생형태 단추(KOSHA 12종: 떨어짐·넘어짐·깔림·부딪힘·맞음·끼임·절단베임·
     감전·화재폭발·이상온도·유해물질·질식 + 기타), 사고 내용.
  2. 다친 사람 — 구성원 선택 또는 외부인 이름, 부위, 정도, 예상 휴업일, 병원.
     (아차사고면 이 구간은 접힘)
  3. 바로 한 조치 — 응급조치, 작업 중지 여부, 대피 여부.
  4. 원인·재발방지 — 원인, 대책 n개(내용·담당·기한). 위험요인 카드와 같은 모양.
  5. 사진 — 유료. 저장 뒤 상세에서 붙인다(첨부는 id 가 있어야 한다).
  저장하면 상세로 돌아간다.
- **상세 `/incidents/[id]`**: 맨 위 **할 일 목록**(자동, 기한, 완료 체크 + 증빙 메모·
  시각·사람). 그 아래 내용·재해자·조치·재발방지 이행·사진·변경 이력.
  할 일 종류:
  - 작업 중지·대피·위험요인 제거 (모두)
  - 노동부 즉시 보고 (중대재해만) — 전화·팩스 번호 안내, 보고 시각·누구에게 적기
  - 산업재해조사표 제출 (보고 대상↑) — D+30 기한, 제출일·방법 적기
  - 수시 위험성평가 (모두) — 지시서·표준서가 있으면 `/standards/{id}/assessments/new?kind=AD_HOC&incident={id}` 로 가고 사전조사 "재해·아차사고 이력" 이 채워진다
  - 재발방지대책 이행 (모두) — 대책마다 완료
  - 근로자 공유 (모두) — 공지사항 글 만들기 단추 + TBM 확인
  - 경영책임자 확인 (중처법 적용 회사) — 서명, 반기 점검 카드와 연결
  모든 할 일이 끝나야 **종결**. 종결 뒤 수정은 잠그고 관리자만 다시 연다.
- **작업자 신고**: 작업자 링크 화면(`/w`)과 작업자 홈에 "아차사고·사고 신고" 44px
  단추. 세 칸(무슨 일·어디·사진) → 관리자 전원 푸시 → 관리자가 상세를 채운다.
  신고자에게 "접수됐습니다" 표시. 은폐 금지·근로자 참여의 흔적이 된다.
- **연결**: 관리자 홈 타일 "처리 중 사고 의무 n", 안전회의 수집 항목에 그 주 사고,
  반기 점검 카드에 "이 반기 재해·아차사고·미완료 의무", 위험성평가 사전조사에 최근
  사고 자동 제안.
- **대응 매뉴얼** (중처법 4조 8호): 회사정보에 "중대재해 대응 절차" 기본 문안(작업
  중지 → 대피 → 119·구호 → 노동부 보고 → 현장 보존 → 원인 조사 → 재발방지). 실시규정과
  같은 방식. 반기 점검 카드가 "매뉴얼 있음·점검함" 을 함께 서명한다.
- **산업재해조사표 출력** (유료): 별지 30호 서식으로 인쇄·PDF. 우리 데이터로 채울 수
  있는 칸(재해자·일시·장소·발생형태·원인·재발방지)은 채우고, 사업자등록번호·업종
  코드·근로자대표 확인은 빈칸으로 두어 사장님이 마저 적는다.

### 3-3. 데이터
```
incidents            id, company_id, kind(NEAR_MISS|INJURY), occurred_at, location_id, location_detail,
                     work_order_id, work_order_snapshot jsonb, standard_id, occurrence_type,
                     description, immediate_action, work_stopped bool, evacuated bool,
                     cause, grade(NEAR_MISS|MINOR|REPORTABLE|SERIOUS), serious_under_scpa bool,
                     status(OPEN|CLOSED), reported_by, reported_via(MANAGER|WORKER), created_at,
                     closed_at, closed_by, retention_until(+3y)
incident_victims     incident_id, user_id NULL, name, body_part, injury, expected_leave_days,
                     fatal bool, treatment_months, hospital
incident_actions     incident_id, measure, responsible_user_id, due_on, done_at, done_by, note
incident_duties      incident_id, kind, due_on NULL, done_at, done_by, note   -- 할 일 목록
companies            + incident_response_manual text (기본 문안)
attachments          target 'incident' 활성화
audit_logs           INCIDENT_CREATE / UPDATE / DUTY_DONE / CLOSE
```
삭제 없음(은폐 금지). 수정은 감사 로그. 안전회의 `INCIDENT` 항목은 그 주 `incidents`
를 모은다.

### 3-4. 권한·요금
- 작업자: 신고, 자기 신고 열람. 관리자: 전체, 종결, 경영책임자 확인.
- 무료: 기록·할 일 목록·수시평가 연결·작업자 신고·푸시. 유료: 사진, 조사표 출력, SMS.

### 3-5. 단계
1. **1단계** — 테이블, 등록·상세·목록, 할 일 목록 자동 생성, 작업자 신고, 홈 타일,
   안전회의·반기 점검 연결, 수시평가 연결. 대응 매뉴얼 기본 문안.
2. **2단계** — 조사표 인쇄·PDF(유료), 통계(연간 재해·아차사고 추이, 발생형태별).
3. **3단계** — SMS, 산재 신청 안내, 중처법 교육 이수 기록.

## 4. 결정이 필요한 것
1. 작업자 신고에 익명을 허용할지. (추천: 허용. 은폐를 막는 게 먼저다. 이름은 관리자가
   나중에 적는다.)
2. 재해자에 외부인(협력업체·방문객)을 허용할지. (추천: 허용. 도급 사업장에서 흔하다.)
3. 조사표 출력을 유료로 둘지. (추천: 유료. 기록·할 일은 무료라 법 대응은 무료로도 된다.)
4. 발생형태를 KOSHA 12종으로 갈지 5종으로 줄일지. (추천: 12종. 조사표에 그대로 쓴다.)
