# 심플안전 디자인 헌법

화면을 만들거나 고칠 때 지키는 규칙이다. 규칙은 짧고, 이유가 붙어 있고, 코드 어디에
있는지가 적혀 있다. 여기 없는 것은 자유이고, 여기 있는 것을 어기려면 이 문서를 먼저
고친다. (2026-09-22 기준. 세부 근거는 `docs/dev-log.md`.)

## 0. 한 줄

**고령화된 제조 현장에서, 장갑 낀 한 손으로, 문의 없이 오늘 바로.**
모든 결정은 이 문장으로 되돌아온다.

영세·소규모 업체를 위한 시스템이다. 업무분장은 관리감독자·안전관리자·작업자 세 그룹과
선택 입력 업무 비고로 충분하다. 별도 조직·직책·업무분장 체계를 늘리지 않는다 (2026-10-07).

## 1. 앱처럼 (좁은 화면, 960px 이하)

1. **문서가 아니라 본문만 스크롤된다.** 상단바는 틀에 고정, 본문(`main`)이 스크롤
   영역이다. 주소창이 접히지 않고 튕김도 본문 안에서만 난다. 화면이 바뀌면 본문을
   맨 위로 올린다. — `globals.css` "앱 틀", `app-shell.tsx`
   틀의 높이·위치는 보이는 영역(visualViewport)이다 (`viewport-height.tsx`).
   키보드가 올라오면 안드로이드는 문서를 줄이고(`interactive-widget=resizes-content`),
   iOS 는 보이는 영역만 밀므로 틀을 그만큼 따라 옮긴다. 키보드가 열린 동안
   (`html[data-keyboard="open"]`) 아래 단추 띠는 고정을 푼다 — 남은 화면이
   절반이고 타자 치는 동안 저장은 쓸 일이 없다.
2. **첫 화면은 한 화면에 들어간다.** 홈(로그인 전·관리자·작업자)은 390×844 에서
   스크롤 없이 요약과 주된 행동이 보여야 한다. 목록만 남는 공간을 채우며 스크롤된다.
   로그인 전 홈의 접힌 아래에는 사업자 표시 하단(6장)만 있을 수 있고, 그 하단은
   첫 화면 밖에서 시작한다(`.public-fold` 가 스크롤 영역 높이를 다 쓴다) — 첫
   화면은 파는 글이지 사업자 등록증이 아니다.
3. **위쪽은 한 면의 색이다.** 상단바 배경 = 본문 배경, 실선 없음. 본문이 밑으로
   들어갈 때만 옅은 그림자(`.is-scrolled`). 상태 표시줄(테마 색)도 배경색.
4. **제목은 한 번, 상단바에.** 본문 머리말에는 설명과 행동 버튼만 남긴다. 왼쪽
   자리는 하나 — 메뉴에 있는 화면이면 ☰, 그 아래 화면이면 ← (`navRoot`,
   `sidebar.tsx`). **← 는 히스토리가 아니라 구조로 간다** (`parent-path.ts`): 한 단계
   위 화면(지시서 → 목록, 점검 기록 → 지시서). 발급 직후 ← 가 방금 지나온 폼으로
   되돌아가면 안 된다. 화면 없는 중간 주소는 건너뛴다.
5. **공지 띠는 틀 안에서 접는다.** 검은 띠가 맨 위에 있으면 무엇을 해도 웹 배너다.
6. **긴 폼은 한 장이고, 길잡이는 고정한다.** 단계 마법사(이전·다음)를 쓰지 않는다.
   뒤 단계가 숨으면 확인하러 되돌아가야 하고 엄지가 갈 단추가 셋이 된다. 구간
   칩(`JumpNav`, `.jump-nav`)은 위에(`top: 0`) 붙어 지나는 구간이 켜지고, 저장·발급은
   아래에(`.wo-actions`, `.sticky-actions`, `.inspection-form-actions`) 붙는다.
   딸려온 값(표준서의 위험성평가·체크리스트)은 채운 채 접는다(`.std-fold`).
   "이게 뭔가요?" 의 답은 언제나 확인 창과 같은 시트·카드다(`HelpDialog`). 부르는
   자리는 둘이다 — 한 줄로 물어야 하는 것은 글 단추(`variant="text"`, 예: "어떤
   작업이 PTW 대상인가요?"), 구간 머리나 라벨에 딸리는 짧은 안내는 그 자리에 붙는
   물음표(`variant="icon"` · `"inline"`). 어느 쪽이든 누르는 자리는 44px 이다.
   라벨 옆 물음표는 그림을 줄이되 44px 상자는 음수 여백으로 숨긴다
   (`.help-dialog-icon--inline`). 물음표를 라벨에서 떼어 폼 오른쪽 끝에 띄우지
   않는다 — 무엇에 대한 물음인지 사라지고 좁은 화면에서 잘린다.
7. **옆으로 미는 띠는 크기를 격리한다.** `contain: inline-size`. 내용 너비가 문서의
   최소 너비로 번지면 모바일 브라우저가 화면을 그 너비로 넓혀 축소해 버린다.
   띠 안의 현재 항목은 띠만 `scrollTo` 로 민다 — `scrollIntoView` 는 조상까지 민다.
8. **스크롤 영역의 위 여백은 padding 이 아니라 첫 자식의 margin.** padding 위로는
   고정 머리가 올라가지 못해 그 띠에 지나가는 내용이 비친다.

## 2. 색

토큰(`globals.css :root`)만 쓴다. 색 코드를 직접 적지 않는다.

| 역할 | 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- | --- |
| 주조 | `--brand` | `#0f5b3c` | 버튼, 링크, 현재 단계, 워드마크, 로그인 전 머리 배경 |
| 주조 진하게 | `--brand-strong` | `#0b482f` | hover, 강조 글자 |
| 주조 연하게 | `--brand-soft` / `--brand-softer` | `#e4efe8` / `#f1f7f3` | 선택된 칩·행, 아바타 |
| 포인트 | `--accent` | `#f2b705` | 로고의 점. "지금·여기": 오늘 배지(진한 칩), 오늘 회차 카드 윗선, 목록의 오늘 줄, 로그인 전 시작 버튼, 강조 단어 |
| 포인트 연하게 | `--accent-soft` + `--accent-ink` | `#fcf1cf` + `#6b4e00` | 이유 아이콘 타일, 혜택 칩, "준비 중", 위험성 "중"(매트릭스 관례) |
| 글자 | `--ink` ~ `--ink-5` | `#15201b` … | 본문 → 보조 → 흐림 순 |
| 배경 | `--bg` / `--surface` | `#f3f3ee` / `#fff` | 화면 바탕 / 카드·입력칸 |
| 선 | `--line` 계열 | `#e4e6e0` … | 테두리 |
| 상태 | `--ok` / `--ok-soft` | `#2f7d5a` | 완료·양호·승인 (글자, 연한 칩) |
| 상태 | `--danger` / `--danger-soft` | `#b83a12` | 삭제·취소·오류·불량·미조치·위험성 상 |
| 상태 | `--info` / `--info-soft` | `#2c5f8a` | 진행·대기·안내 (글자, 연한 칩, 안내 띠) |

규칙:
- **초록은 "여기를 누르면 앞으로 간다"**, 노랑은 **포인트 — "지금·여기"** 다. 로고의
  점처럼 작고 진하게, 한 화면에 한두 곳(오늘 배지·오늘 카드 윗선). 노랑으로 누르는
  버튼을 만드는 곳은 로그인 전 머리(초록 위) 한 곳뿐이다.
  예외 하나: 멤버십 안내의 **"요금제 보기" 링크는 노랑 밑줄**이다(사장님 2026-10-08) —
  토스트(검정 위)는 노랑 글자, 밝은 바탕은 연노랑 형광펜 + `--accent-ink` (`.membership-link`).
- **노랑은 경고·대기 색이 아니다.** 흐린 노란 바탕을 깔아 "주의" 를 말하지 않는다 —
  포인트가 흐려진다. 빠졌다·막혔다·불량은 빨강, 기다린다·진행 중은 파랑, 끝났다는 초록.
  알림 띠의 기본은 회색이다. 위험성 "중" 의 노랑만 위험 매트릭스 관례로 남긴다.
- 노랑 글자는 연노랑 바탕 위에 `--accent-ink` 로만. 흰 바탕에 노란 글자는 안 읽힌다.
- 빨강은 지우기·취소·오류에만. 미조치 건수처럼 "주의" 는 빨강 숫자 하나로 충분하다.
- **상태색은 글자와 작은 칩까지.** 초록 = 끝났다·양호·승인, 빨강 = 빠졌다·취소·불량·
  미조치·위험성 상, 파랑 = 진행 중·대기·안내. 큰 면(카드 배경·머리)에는 칠하지 않는다.
  **종결·잠김은 회색**이다 — 사고 종결은 끝낸 성과가 아니라 닫힌 서류라 초록을 주지 않는다. 같은 뜻은 어느 화면에서든 같은 색이다 — 상태 4칸의
  값(`data-tone`), 배지(`.wo-risk-level[data-tone|data-level]`), 알림 띠
  (`.wo-notice[data-tone]`, 기본은 노랑), 점검 항목의 고른 값(양호 초록·불량 빨강).
- 카드는 흰색, 바탕은 종이색. 이 대비가 구획을 나누므로 선을 더 긋지 않는다.
- **스크롤 영역(main)에는 위아래 padding 을 두지 않는다.** sticky 머리·띠는 padding
  안으로 들어가지 못해 그만큼 떠서 서고, 그 밑으로 내용이 지나간다. 위 여백은 첫
  자식의 margin, 아래 여백은 `::after` 조각이며 아래 띠가 있는 화면은 조각을 뺀다.
  모바일 e2e 가 스크롤 중 띠의 아래 끝이 화면 바닥과 같은지 잰다.
- **틀의 높이는 실제 보이는 영역이다.** `100dvh` 가 아니라 visualViewport 높이
  (`--app-h`, `viewport-height.tsx`). iOS 는 키보드를 내린 뒤 화면을 되돌리지 않는
  일이 있어, 그때 아래 단추 띠가 화면 중간에 뜬다. 키보드가 열린 동안에는 띠가
  키보드 바로 위에 온다.

## 3. 글꼴

- **글꼴은 하나, Pretendard (가변).** `--font-sans`. 제목도 굵기(700–900)로만 구분한다.
  영문 전용 글꼴을 따로 두지 않는다. — `layout.tsx`, `globals.css`
- 본문 14px, 보조 12–13px, 화면 제목 17px(상단바)·24px(넓은 화면), 로그인 전 h1 24–40px.
- 입력칸은 항상 16px 이상 (iOS 가 확대해 버린다).
- **입력칸은 플로팅 라벨 하나다.** 라벨이 칸 안에 흐리게 있다가, 누르거나 값이
  들어가면 작아져 윗선에 앉는다 (`FloatField` · `FloatTextarea` · `FloatSelect`,
  `components/ui/float-field.tsx`, `.float-field`). 위 라벨 줄이 없어 폼이 짧고,
  좁은 화면에서도 짧은 칸을 나란히 세울 수 있다(비상연락처 [이름] [휴대폰]).
  - 예시 문구는 `hint` — 라벨이 칸을 차지하므로 누른 뒤에만 흐리게 보인다.
    칸 아래 안내는 `note` (화면 읽기가 칸과 함께 읽는다).
  - 날짜·시간·고르기(select)는 칸 안에 늘 글자가 있어 라벨이 처음부터 올라가 있다.
  - 라벨은 한 줄이다. 넘치면 말줄임이 되니 짧게 쓰고, 묶음 이름은 구간 제목·legend 에
    맡긴다("비상연락처" 아래 "이름 1").
  - 날 `<input>`·`<textarea>`·`<select>` 는 쓰지 않는다. 체크박스·라디오·파일·숨김·
    검색칸만 예외. 그 밖에 꼭 필요하면 바로 위 줄에 `헌법 3장 예외: 이유` 를 적는다.
    기계가 검사한다.
- `word-break: keep-all` — 한국어는 어절 단위로 줄을 바꾼다. 긴 주소만 `anywhere`.
- 숫자는 `tabular-nums` (타일, 건수).

## 4. 형태와 크기

- 모서리 8 / 12 / 16px (`--radius-sm` / `--radius` / `--radius-lg`). 칩은 999px.
- **누르는 것은 44px** (최소 40px). 버튼·입력칸·탭·카드형 링크·도움말 ?·×.
  본문 속 글자 링크만 예외. 모바일 e2e 가 40px 미만을 잡는다 (`mobile-layout.spec.ts`).
- 체크박스·라디오는 그림이 작아도 **누르는 자리(라벨)를 44px** 로. 사람 고르기는 칩
  전체가 체크박스다 (`people-picker.tsx`).
- 좌우 여백 16px(좁은 화면). 띠·고정 바는 `-16px` 로 화면 끝까지 민다.
- 주된 행동은 채운 버튼 하나. 한 줄에 채운 버튼이 둘이면 잘못됐다.
- **한 화면의 세 구역 — 내용 · 딸린 문서 · 기록.** 화면이 보여 주는 것은 세 가지뿐이고
  각각 모양이 다르다. 어느 메뉴에서든 같은 모양은 같은 뜻이다 (사장님 결정 2026-09-30).
  - **내용**(이 문서 자체의 것): 흰 카드(`--surface`), 실선. 폼에서는 채우는 순서대로
    구간에 번호를 단다(`.std-step-no`).
  - **딸린 문서**(함께 만들어지지만 따로 사는 것 — 표준서의 위험성평가, 지시서의
    허가서): 그 앞에 "별도 문서 · ○○" 띠(`.std-form-divider`)를 긋고, 주조색 연한 바탕
    (`--brand-softer`)과 왼쪽 굵은 주조색 선(4px)의 카드(`.std-form-section--assessment`,
    `.std-detail-section--assessment`). 카드 머리에 아이콘과 "별도 문서 · 함께 등록"
    같은 작은 머리말(`.std-assessment-eyebrow`).
  - **기록**(이력·감사·회차 목록처럼 지나간 것): 그 앞에 "기록" 띠(회색,
    `.std-form-divider--log`), 종이색 바탕(`--surface-2`)에 점선 테두리의 카드
    (`.std-detail-section--log`), 제목은 작고 흐리게. 기록에는 사유·메모 같은 긴 글을
    펼치지 않는다 — 언제·누가·무엇이 한 줄이면 된다.
  - 딸린 문서와 기록은 내용 뒤에 온다. 내용 사이에 끼우지 않는다. 한 화면에 세 구역이
    다 있을 필요는 없지만, 있으면 이 순서다.
  - 카드 없이 선으로 나누는 상세(지시서·사고·평가)에서도 카드 두 가지는 같다. 띠와 카드는
    `.zone` 으로 묶어 넣는다(본문의 큰 간격이 띠와 카드 사이를 벌리지 않게). 어디에 무엇이
    딸린 문서인가: 표준서 → 위험성평가, 지시서 → 위험성평가·작업허가서, 사고 → 산업재해조사표.
    기록은 변경 이력(지시서)·처리 기록(사고)·회차 이력(평가·표준서)·개정 이력(표준서). 기록
    줄은 `HistoryLog`(언제·누가·무엇, 최근 5줄 뒤는 접힘).
  - 이유: 같은 흰 카드가 이어지면 표준서의 한 구간인지 다른 문서인지 읽는 사람이 매번
    맞춰야 한다. 반대로 메뉴마다 새 모양을 만들면 지겹고 헷갈린다. 세 가지 모양만 쓴다.

- **단추는 역할이 다섯이고 모양이 다섯이다** (사장님 2026-10-06: "버튼이 다 비슷해 생동감이
  없다"). 주 행동(화면에 하나, `btn-primary` 초록 채움) · 보조 행동(상태를 바꿈,
  `btn-secondary` 흰 바탕 테두리) · 위험 행동(`btn-secondary` + `data-tone="danger"` 빨간
  글자·테두리, 확인 창 안은 `btn-danger`) · 이동(아무것도 바꾸지 않고 다른 화면으로,
  `go-link` 상자 없는 글) · 기호 단추(`icon-button`, 그림만 + `aria-label`).
  이동은 둘로 나뉜다: **가서 하는 것**은 글 뒤 화살표(오늘로 →, 초기화 →, 이어서 작성 →,
  평가하러 가기 →, ← 회차 목록), **읽기만 하는 것**은 글 앞 물음표(`CircleHelp`: 대응 절차,
  산업재해조사표, 회의록, 점검 기록, 작업지시, 허가서, 게시글 보기) — 머리의 물음표 안내와
  같은 "정보" 그림이다 (사장님 2026-10-06: "화살표만 고집하지 말고 정보면 물음표").
  목록 줄 안의 작은 행동은 `btn--sm`(40px). 옛 `primary-button`·`ghost-button`·
  `secondary-button` 은 없다. "점검 기록으로·회차 목록·보기·열기" 같은 이동을 단추로
  그리면 진짜 행동이 묻힌다.
  - **단추마다 그림 하나, 뜻마다 그림은 하나로.** 저장 `Save`, 발급·신청 `Send`, 조회·검색
    `Search`, 고치기·이어서 `PenLine`, 복사 `Copy`, 인쇄 `Printer`, 취소(창 닫기 성격) `X`,
    지시서 취소 `Ban`, 버리기·삭제 `Trash2`, 폐기 `Archive`, 승인·확인·완료 `Check`,
    일괄 승인 `CheckCheck`, 추가 `Plus`, 다시 열기 `RotateCcw`, 서명 `PenLine`, 이동 `ArrowRight`.
  - **지금·여기의 단추 하나는 노랑**(`btn-accent`, 오늘 배지와 같은 포인트색): 작업자의
    오늘 TBM 확인. 화면에 하나뿐이고 다른 주 행동은 초록이다.
  - **창의 닫기는 오른쪽 위 × 하나**(`reason-dialog-close`, `aria-label="닫기"`). 아래 단추
    줄에 글자 "닫기" 를 두지 않는다. 확인 창의 "확인"·"취소" 는 답이라 글자 단추로 둔다.
  - 기계 검사(8장): 옛 클래스 이름, 그림 없는 `btn-*` 단추, 글자 "닫기" 단추는
    `scripts/check-constitution.mjs` 가 막는다.

## 5. 움직임과 피드백

- **누르면 즉시 반응.** 화면 이동은 전체화면 로고(`loading.tsx`, 자식 폴더마다 재수출),
  제출은 버튼 글자가 "저장 중…" 으로. 아무 신호 없는 대기는 없다.
  새 화면 폴더를 만들면 검사 항목: `find src/app -name page.tsx` 의 각 폴더에
  자식 폴더가 있으면 `loading.tsx` 가 있어야 한다 (8장 검증).
  loading.tsx 는 세그먼트가 바뀔 때만 뜨므로, 같은 화면에서 쿼리만 바뀌는 이동(회차 열기
  `?session=`, TBM 확인 `?type=`, 조회 폼)은 `components/shell/nav-pending.tsx` 가 링크·GET
  폼을 누르는 순간 같은 로고를 띄우고 주소가 바뀌면 내린다 (사장님 2026-10-07). 루트
  레이아웃에 `<NavPending />` 이 빠지면 기계 검사(8장)가 잡는다.
- **스크롤 등장 효과는 로그인 전 홈에만.** 파는 화면이라 내리면 글과 미리보기가 떠오른다
  (AOS 의 CSS, `data-aos` + `.aos-animate`, `features/dashboard/scroll-reveal.tsx`). 일하는
  화면에는 없다 — 기다리게 하는 움직임이다. 움직임을 줄이라는 기기(prefers-reduced-motion)
  에서는 바로 다 보인다.
- **확인은 앱 안의 시트로** (`useConfirm`). 브라우저 `confirm()` 금지. 되돌리기
  어려운 동작(삭제·취소·폐기·퇴사)은 빨간 버튼, 나머지는 초록.
- **막힌 행위의 안내는 그 자리에서 잠깐.** 멤버십 안내를 화면에 미리 써 두지 않는다
  — 안 막힌 사람까지 읽게 된다. 잠긴 것(무료의 1주일 밖 회차·지시서)은 목록에 자물쇠로
  남기고, 단추(인쇄·사진 붙이기·첨부)는 숨기거나 비활성으로 두지 않는다. 잠긴 카드·줄은
  자물쇠만이 아니라 **어디를 눌러도** 안내가 뜬다(`PaidLockRow`, 카드의 onClick). 누르면 토스트
  (`useToast`, `usePaidToast`, `PaidLockButton`, `.toast`)가 몇 초 뜨고 사라진다. 요금제
  링크는 그 안에 — 멤버십 안내에는 **모두** 이용·관리(요금제) 화면 링크를 단다(`MembershipLink`, 서버가 돌려준 오류 글은 `WithMembershipLink`). 사이드바 맨 위 회사 카드는 **회사 정보**(`/company`)를 연다 — 기본 정보·회사코드·인원(접힘, 인원관리로)·현재 요금제(요금 안내로)가 한 장에. 요금제(`/billing`)는 기준정보 메뉴에 두지 않고 그 화면의 "요금 안내" 와 멤버십 안내 링크로 간다. 작업자 링크 화면은 링크 없이. 멤버십 벽 화면(모니터링)만 예외로 한 줄 +
  요금제 단추. (사장님 2026-10-05: "그 행위를 했을 때 막으면서 휘발성 메시지로".)
- **필터 칩은 화면에서 거른다.** 서버는 기간·검색어로 한 번 조회하고, 오늘·이번 주·미이행
  같은 칩은 받은 목록을 다시 조회 없이 거른다(`aria-pressed` 단추, `features/inspections/
  log-list.tsx`). 누르면 바로 바뀌고 주소가 쌓이지 않는다. 기간을 바꾸는 것만 서버로.
- **저장하면 온 곳으로 돌아간다.** 보기 화면에서 "고치기" 로 들어왔으면 저장 뒤
  그 보기 화면으로. 편집 화면에 "저장했습니다" 만 띄우고 머무는 것은 잘못이다.
  예외는 아직 쓰는 중인 초안의 임시저장 하나.
- **저장 후 못 고치는 것은 저장 전에 요약을 보여 준다** (점검 저장).
- **머리말의 주 행동은 오른쪽에.** 넓은 화면은 제목 오른쪽, 좁은 화면도 단추 줄을 오른쪽
  끝에 맞춘다(`PageHeader actions`). 글 링크가 같이 있으면 그 왼쪽에. 목록 화면의 주 단추
  (사고 등록·작업 지시하기·표준서 만들기·작업 선택)는 모두 머리 안에 둔다 (사장님
  2026-10-06). **폼 끝의 저장 줄도 오른쪽 끝**(`form-actions`), 되돌리기(취소)는 그 왼쪽,
  삭제·버리기처럼 되돌리기 어려운 것은 왼쪽에 떨어뜨린다. 글 링크·도움말은 왼쪽에 남아도
  된다. 카드 안의 하나짜리 주 단추(새 회차 위험성평가·요금표 보기)도 오른쪽.
- **좁은 화면의 세로 간격은 한 자(16px)다.** 머리말은 설명 → 단추 줄 순으로 쌓고 사이
  12px. 블록(상태 칸·카드·알림 띠·값 띠) 사이 16px, 구간 안 20px. 칩 띠 바로 밑 구간은
  윗선 없이. 단추 묶음에 붙은 여백(`.wo-actions` 24px)은 머리말 안에서는 0.
- **목록은 10건씩 한 쪽이다.** 긴 목록을 한 화면에 다 풀지 않는다 — 좁은 화면에서는
  끝없는 스크롤이 된다. 목록 아래 한 줄 `[‹ 이전] 2 / 5 [다음 ›]` (`Pager`, `ClientPager`,
  `.pager`), 한 쪽뿐이면 안 그린다. 탭이나 조건이 바뀌면 1쪽부터. 고르는 창(팝업) 안의
  목록과 12주처럼 상한이 작은 목록은 예외.
- **성격이 다른 값을 점(·)으로 이어 문장처럼 놓지 않는다.** "관리자 · 웹 · 사후 입력" 은
  읽는 사람이 어느 값이 무엇인지 맞춰야 한다. 이름표 있는 줄(`Facts`, `dl.wo-facts`)이나
  이름표 있는 값 띠(`StatStrip`, `.stat-strip`)로 놓는다. 점으로 잇는 것은 같은 성격의
  값(장소 · 조, 날짜 ~ 날짜)뿐이다.
- 미저장 입력은 기기에 보관했다가 다시 열면 "이어서 작성 / 버리기" 를 묻는다. 긴 폼
  (표준서·지시서)은 그와 별도로 **임시저장**이 있다 — 필수 칸 하나(이름)만으로 서버에
  "작성 중" 으로 남기고 목록으로 돌아간다. 다른 기기·다른 사람도 이어서 쓴다.

## 6. 문구

- **돈 이야기는 "멤버십" 으로 한다. "유료" 라고 쓰지 않는다** (사장님 2026-10-08).
  "유료 요금제에서 씁니다" 는 막혔다는 말보다 돈을 내라는 말로 먼저 읽힌다.
  막힌 자리의 한 줄은 "○○은 멤버십에 가입된 회사만 쓸 수 있습니다", 기능 묶음은
  "멤버십 기능", 바꾸는 행위는 "멤버십 가입". 받침이 있어 조사가 달라진다 —
  멤버십**은**·**으로**·**이면**. 무료 쪽은 그대로 "무료". 약관(`features/legal`)만
  예외로, 처음 한 번 "멤버십(유료 이용 계약)" 이라고 무엇인지 밝힌다 — 청약철회가 걸리는
  대상이라 법 문서에서는 이름만으로는 부족하다. 기계 검사가 잡는다.
- **사장님 시각에서, 당기게 쓴다.** 공개 화면(홈·가이드·진단·문의)은 파는 글이다.
  읽는 사람이 "이거 써야겠다" 가 되게 쓴다. 면책·책임 회피·단서("법적 책임을
  대신하지 않는다", "실제 인정은 별도 심사", "정확하지 않을 수 있다", "최종 판단은
  기관에 확인")는 쓰지 않는다. 출처가 필요하면 맨 아래 한 줄 "출처: …" 로 끝.
  약관·개인정보 동의 한 줄(로그인)은 예외.
- **명사형으로 끊는다.** 마케팅·안내 문구에서 "~합니다/~됩니다" 를 늘어놓지 않는다.
  `'시작 요금' 없는` 처럼 짧게. 설명은 한 줄.
- **구간 머리에 설명 문단을 두지 않는다.** 이 구간이 뭔지·완료 기준이 뭔지·알림이 어디로
  가는지는 제목 오른쪽 물음표(`HelpDialog variant="icon"`, `.wo-section-head` /
  `.std-section-head`)가 연다. 목록 위의 안내 문단(`wo-muted`)과 화면을 풀어 설명하는
  머리말 부제는 뺀다 — 화면에 남는 글은 제목·값·단추뿐이다. 값인 부제(상태 · 작성자)와
  빈 상태의 한 줄은 둔다. (사장님 2026-10-05: "글이 너무 많아, 피로하다".)
- **없는 것은 없다고.** 가짜 데이터·예시 숫자를 두지 않는다. 아직 없는 기능은
  "준비 중" 표시를 달거나 빼지, 있는 척하지 않는다.
- 제목은 이동 경로의 마지막 조각과 같아야 한다(상단바가 그걸 보인다).
- 작업자 쪽은 **"구성원은 QR만 찍으면"** 이라고 쓴다. 작업자 링크·QR 은 회사에
  초대된 구성원에게만 나가므로 가입은 되어 있고 로그인 절차만 없다. "로그인 없이"
  라고 쓰면 가입도 없는 것처럼 읽힌다.
- 오류 문구는 무엇이 잘못됐고 무엇을 하면 되는지 한 문장씩.

- **약관·처리방침(`/terms`, `/privacy`, `features/legal`)은 법 문서라 이 장의 예외다.**
  단서와 한도를 적는 것이 그 문서의 일이다. 다른 공개 화면에서 그 문장을 끌어다
  쓰지 않는다 — 링크만 건다.
- **사업자 표시는 면책이 아니다.** 상호·대표·사업자등록번호·주소·고객센터·이메일은
  전자상거래법이 초기 화면에 요구하는 것이라 로그인 전 공개 화면 하단(`SiteFooter`)에
  작게 한 덩어리로 둔다. 머리는 서비스 이름(심플안전)이고 상호·대표는 작은 한 줄,
  나머지는 "사업자 정보" 뒤에 접는다 — 상호가 서비스 이름과 다를 때 첫인상을 흐리지
  않게. 시행규칙이 상호·대표 외의 항목은 연결 화면(접힘)으로 두는 것을 허용한다. 로그인한 작업 화면에는 두지 않고 도움말(`/help`) 맨 아래
  "서비스 제공자" 에. 마이페이지는 내 정보의 자리다.

## 7. 화면별 첫 화면

- **로그인 전:** 초록 머리(누구에게, 왜) + 시작·진단 버튼 + 이유 넷.
  - 이유는 카드 전체가 단추. 누르면 긴 설명이 창(`.reason-dialog`, 좁은 화면은
    아래 시트)으로 뜬다. 접기(`<details>`)는 쓰지 않는다 — 열리면 아래 카드가
    밀려 한 화면 규칙이 깨지고, 닫힌 채로는 카드 사이가 빈다. 아이콘(동전·방패·
    QR·지구)과 제목·한 줄 요약·혜택 칩은 카드에 늘 보인다. 좁은 화면은 카드 넷이
    남는 높이를 나눠 갖고(글자 크기는 넓은 화면과 같다), 넓은 화면은 2×2.
  - 로그인 전 홈은 파는 글이다. 면책·단서("법적 책임을 대신하지 않는다", 심사
    기관, 적용 업종 조건)는 쓰지 않는다. 그런 말은 약관·도움말의 자리다.
  - 넓은 화면의 머리 오른쪽에는 작업자 화면 모형(`.hero-phone`)을 둔다. 모형에는
    실제로 있는 화면(오늘 점검 목록·허가서 승인·QR)만 그리고, 아직 없는 기능(언어
    칩·게이지)은 그리지 않는다. 좁은 화면에서는 숨긴다.
- **관리자 홈:** 오늘 타일 한 줄(오늘 작업·TBM 미확인·미조치·초안) + 시작 버튼
  한 줄 + **처리할 일**(허브: 가입 승인·불량 조치·PTW 승인·사고 뒤 할 일·위험요인
  조치·평가 필요 표준서가 한 목록, 없으면 한 줄) + 예정·진행 목록 + 공지·안전소식.
  메뉴마다 알림 칸을 따로 두지 않는다 — 할 일은 홈의 한 곳에 모인다.
- **작업자 홈:** 오늘 작업 카드(안에 TBM 확인·작업 중 점검) + 놓친 회차 한 줄 +
  다른 작업 보기 + 아차사고·사고 신고 한 줄. 숫자 타일 없음.
- **작업자 링크 화면(`/w`):** 오늘 회차부터, 홈 화면에 추가 안내 한 번.
- **공개 화면(로그인·가이드·진단·문의·온보딩):** 홈과 같은 상단바(`.topbar--public`).
  화면마다 머리가 다르면 다른 서비스로 보인다.
- **도움말(`/help`):** 시작 세 단계(표준서 → 지시서 → 현장 점검) → 자주 묻는 것(접힘) →
  더 보기(안전법 가이드·진단·요금제·문의) → 서비스 제공자·약관 링크. 사이드바 "도움말" 이
  여기로 온다. 설명서가 아니라 길잡이다.
- **작업지시 작성·편집:** 한 장. 작업 정보(표준서 고르기 → 작업명·방법·조·PTW) →
  위험성평가 → 일정·인원·장소 → 체크리스트. 따로 "발급" 구간은 없다 — 무엇을 하는지는
  발급 확인 창이 말한다. 표준서를 고르기 전에는 고르는 칸만 있다. "새 표준서
  만들기" 는 표준서가 없는 회사만 밖에, 하나라도 있으면 찾기 창 안에만 둔다. 표준서 모드에서
  위험성평가는 **표준서의 승인된 평가를 그대로 쓴다** — 접힌 채 읽기만 하고 지시서에서
  고치지 않는다(고치면 검토 없는 평가가 생긴다; 바꾸려면 표준서에서 새 회차). 발급하면
  그 평가를 가리키고 그 시점의 내용이 스냅샷으로 남는다. 사본 행을 만들지 않으므로
  위험성평가 목록이 부풀지 않고 조치는 한 곳에서 한 번 센다. 체크리스트는 "n건이
  채워졌습니다" 로 접힘, 간이평가는 펼침. 아래 고정
  바는 (초안이면 삭제) · 임시저장 · 지금 발급하기. 좁은 폰에서 삭제는 휴지통만.
  다른 관리자 검토는 폼 아래 접힘. 구성원 초대는 작업자 선택 창 안(새 탭).
  PTW 는 불필요·필요 단추 + "어떤 작업이 해당되나요?".
  폼 안의 설명은 한 줄이 넘으면 줄인다. 누르면 무엇이 되는지는 단추 이름과 확인
  창이 말한다.
- **발급된 지시서 상세:** 한 장. 제목 줄(조·장소 · 발급 시각) → 상태 4칸 → 오늘 회차
  카드(한 줄 + TBM 확인하기 · 작업 중 점검하기) → 구간 칩 → 작업 정보(표준서 링크 맨 위 ·
  장소·기간·PTW, 작업방법은 밑에 글로) → 위험성평가 → 일정·인원(회차 목록) → 체크리스트 → QR·전달. 탭 없음.
  위험성평가·일정·인원·체크리스트는 접힘(머리에 "위험요인 3건" 식 요약), 작업 정보와
  QR·전달은 펼침. 구간 칩을 누르면 접힌 구간이 열린다.
  발급 직후엔 QR 구간으로 내려간다. 지시서 번호·버전·출력 시각·판단 기준 표·설명 문단은
  없다(출력물에만). 취소는 제목 오른쪽 단추 → 사유 창, 변경 이력은 맨 아래 접힘.
- **TBM 확인·작업 중 점검:** 입력만. 머리(작업명 · 회차 날짜·시간) → 위험요인 목록 →
  체크리스트 → 저장. 코멘트 칸은 불량·해당없음일 때만. 기록·회차 목록·관리자 도구는
  "점검 기록" 화면에.
- **점검 기록:** 두 층. 1층은 오늘 회차 카드 + 회차 줄 목록(날짜 · 오늘/예정/지난 ·
  TBM n/m · 작업 중 n건 ›) + 불량. 2층은 회차 하나(시간 · 단추 · 기록 줄 "[TBM] 이름 ·
  시각 · 양호 n 불량 n" · 관리자 사후 입력). 한 화면에 다 펼치지 않는다 — 깊이로 나눈다.
- **표준서 개정:** 승인된 판은 고치지 않는다. "개정 시작" 이 현재 판을 통째로 복사한
  초안을 만들고(단계 사진 참조까지), 초안을 고쳐 "승인" 하면 새 판이 된다. 상세는
  현재 판·작성 중 초안 띠·개정 이력(판마다 보기)을 보여 주고, 지시서 발급과 평가
  회차는 그때의 판 번호를 박는다 ("프레스 금형 교체 (2판)").
- **표준서 작성·수정:** 구간 머리 오른쪽마다 물음표(`HelpDialog` icon) → 무엇·
  어떻게·왜 세 줄(`section-help.tsx`). 맨 아래 최초 위험성평가는 표준서의 한 구간이
  아니라 함께 등록되는 별도 문서다 — "여기부터 위험성평가" 띠로 끊고, 주조색 연한
  바탕과 왼쪽 선의 카드(`.std-form-section--assessment`)에 "별도 문서 · 표준서와 함께
  등록" 머리말을 단다. 사전조사 안전보건정보 칸의 힌트는 "해당없음이라고 적으라" 가
  아니라 현장의 예시(`SAFETY_INFO_HINTS`)다. 판단 기준은 폼에 펼치지 않는다 — 위험요인
  카드의 수준 옆 물음표가 회사 기준을 보여 준다(지시서·평가 회차도 같다). 단계와
  체크리스트는 두 칸씩 미리 있고 빈칸에 예시가 있다. 체크리스트의 이름은
  "안전/품질 체크리스트". 목록의 확정된 표준서는 "확정됨".
- **위험성평가:** 맨 위 숫자 셋(올해 평가·조치 남은 위험요인·평가 필요 표준서) →
  평가가 필요한 표준서 → 평가 목록(전체·유효·조치 필요·만료). 평가 화면은 제목 →
  구분·실시일·유효·작성·승인 한 줄 → 출처 줄(표준서 이름 + "n회차 개정본" 흐리게,
  지시서 이름 + 왜 붙었는지 한 줄; 표준서 지시서의 평가는 둘 다) → 위험요인 카드(계획과
  실제 조치를 나란히) → 안전보건정보 → 판단 기준·참여자. 위험요인 입력은 세 폼
  (표준서 최초평가·평가 회차·지시서 간이평가)이 같은 카드(`RiskItemCard`)를 쓴다:
  위험요인 → 현재 안전조치 → 수준(상·중·하 단추) → 허용 여부(단추) → 감소대책,
  담당·예정일은 접힘 (3단계 판단법 표준 양식의 순서). 판단 기준은 폼에서 적지
  않는다. 회사 기준을 서버가 사본으로 남긴다. 조치 뒤에도 허용 불가면 추가 대책을
  적어야 하고 항목은 계속 "남은 조치" 다 (고시 제13조). 위험성평가 화면 맨 위는
  경영책임자 반기 점검 카드 — 이 반기 숫자와 서명 여부 (중처법 시행령 4조 3호).
  실시규정은 기준정보 > 위험성 판단 기준 아래에 있다.
- **안전사고:** 위험성평가 메뉴와 같은 틀. 목록은 숫자 셋(올해 재해·아차사고·처리 중
  할 일) → 기한이 다가온 할 일 → 탭(전체·처리 중·종결) 목록. 등록은 한 장, 구간 칩 넷
  (무슨 일 → 다친 사람 → 바로 한 조치 → 원인·재발방지), 저장 전에 "이대로 저장하면
  등급은 ○○, 할 일 n개" 를 미리 보인다. 상세의 맨 위는 **해야 할 일** 목록(체크 · 제목/
  근거/기한 · 끝내기) — 기록을 보여 주는 화면이 아니라 남은 일을 끝내게 하는 화면이다.
  그 아래 사고 내용(Facts) → 다친 사람 → 바로 한 조치 → 원인·재발방지(대책 카드, 완료
  적기) → 사진(멤버십). 할 일이 다 끝나야 종결, 종결 뒤 잠김. 삭제 없음.
  작업자의 안전사고 메뉴는 **신고 화면**(세 칸: 무슨 일·어디·사진, 기명)이고 작업자
  링크 화면(/w)에도 같은 단추가 있다. 보내면 관리자 전원에게 푸시. 산업재해조사표
  (별지 30호)는 상세의 단추 → 우리 기록으로 채운 서식, 인쇄·PDF 는 멤버십. 중대재해 대응
  절차는 기준정보 아래, 실시규정과 같은 방식(기본 문안).
- **통합자료실(공지사항·오늘의 안전소식·자료실):** 목록은 제목·한 줄 요약·작성자·날짜 한 행.
  오늘의 안전소식은 심플안전(운영자)이 모든 회사에 보내는 글이다 — 글쓰기는 운영자에게만
  보이고, 작성자는 사람 이름이 아니라 "심플안전". 공지처럼 팝업으로 띄울 수 있다. 홈에는
  공지사항·오늘의 안전소식 칸이 최신 두 건씩 (넓은 화면은 나란히), 전체 보기는 게시판으로.
  글이 없어도 칸은 남긴다 — 어디에 올라오는지 알게.
  글 화면은 문서다: 제목 → 작성자·날짜(오른쪽에 고치기) → 구분선 → 본문 (넓은
  화면 760px). 상단바에는 제목이 아니라 게시판 이름이 남는다 — 제목은 본문의
  일부이고, 어디에 있는지는 상단바가 말한다. 공지 팝업은 홈·작업자 링크 화면에 들어올 때 한
  번, 닫기가 첫 단추이고 "오늘 하루 / 7일간 안 보기" 는 기기가 기억한다. 팝업이
  두 개 이상이면 최신 것부터 하나씩. 푸시 켜기 안내는 멤버십 회사에만, 한 번 닫으면
  다시 띄우지 않는다.

## 8. 검증

- 모든 화면 변경은 `npm run lint`·`typecheck`·`build`, 그리고 일회성 PostgreSQL 로
  `npm run test:orders-ui` (데스크톱·모바일). 모바일 e2e 는 가로 넘침·40px 터치
  타깃·메뉴 서랍 포커스를 잡는다.
- 스크린샷으로 색과 배치를 눈으로 본다. 테스트가 통과해도 이상하면 이상한 것이다.
- **기계가 검사하는 항목** (`scripts/check-constitution.mjs`, `npm run lint` 와
  `npm run build` 앞에서 돈다): 자식 화면 폴더의 `loading.tsx`, 브라우저
  `confirm/alert/prompt`, 위에 뜨는 오류 띠(`form-error`), 기능 CSS 의 색 코드,
  공개 화면의 면책 문구, 상태 표시줄 색 세 곳 일치, Pretendard 외 글꼴, 날 입력칸. 어기면 lint 와 build 가 실패한다.
- **사람이 검사하는 항목**은 저장소 루트 `CLAUDE.md` 의 새 화면 체크리스트다.
  세션 시작 때 자동으로 읽힌다. 저장 후 복귀, 44px, 단추 글자 쪼개짐, 스크린샷.
- 규칙을 어긴 사고가 나면 그 규칙을 기계 검사로 옮길 수 있는지 먼저 본다. 문서에
  한 줄 더 적는 것은 두 번째 수단이다.

## 9. 하지 않는 것

- 하단 탭 바 (지금은 없다. 넣을 때 이 문서부터 고친다).
- 브라우저 `confirm`/`alert`, 문서 스크롤에 기대는 고정 요소, 색 코드 직접 쓰기,
  두 번째 글꼴, 노란 배경의 누르는 버튼(로그인 전 머리 제외), 흰 바탕의 노란 글자,
  가짜 데이터, 한 줄에 채운 버튼 둘.
- **오류를 위에 조용히 띄우는 띠.** 저장은 아래 띠에서 누르는데 오류가 맨 위에
  뜨면 아무 일도 없던 것처럼 보인다. 오류는 안내 창(`FormErrorDialog`)으로 띄운다.
  기계가 검사한다 (`className="form-error"` 금지).
