# 심플안전 디자인 헌법

화면을 만들거나 고칠 때 지키는 규칙이다. 규칙은 짧고, 이유가 붙어 있고, 코드 어디에
있는지가 적혀 있다. 여기 없는 것은 자유이고, 여기 있는 것을 어기려면 이 문서를 먼저
고친다. (2026-09-22 기준. 세부 근거는 `docs/dev-log.md`.)

## 0. 한 줄

**고령화된 제조 현장에서, 장갑 낀 한 손으로, 문의 없이 오늘 바로.**
모든 결정은 이 문장으로 되돌아온다.

## 1. 앱처럼 (좁은 화면, 960px 이하)

1. **문서가 아니라 본문만 스크롤된다.** 상단바는 틀에 고정, 본문(`main`)이 스크롤
   영역이다. 주소창이 접히지 않고 튕김도 본문 안에서만 난다. 화면이 바뀌면 본문을
   맨 위로 올린다. — `globals.css` "앱 틀", `app-shell.tsx`
   틀의 높이·위치는 보이는 영역(visualViewport)이다 (`viewport-height.tsx`).
   키보드가 올라오면 안드로이드는 문서를 줄이고(`interactive-widget=resizes-content`),
   iOS 는 보이는 영역만 밀므로 틀을 그만큼 따라 옮긴다. 키보드가 열린 동안
   (`html[data-keyboard="open"]`) 아래 단추 띠는 고정을 푼다 — 남은 화면이
   절반이고 타자 치는 동안 저장은 쓸 일이 없다.
2. **첫 화면은 한 화면에 들어간다.** 홈(로그인 전·관리자·작업자)은 390×844 에서
   스크롤 없이 요약과 주된 행동이 보여야 한다. 목록만 남는 공간을 채우며 스크롤된다.
3. **위쪽은 한 면의 색이다.** 상단바 배경 = 본문 배경, 실선 없음. 본문이 밑으로
   들어갈 때만 옅은 그림자(`.is-scrolled`). 상태 표시줄(테마 색)도 배경색.
4. **제목은 한 번, 상단바에.** 본문 머리말에는 설명과 행동 버튼만 남긴다. 왼쪽
   자리는 하나 — 메뉴에 있는 화면이면 ☰, 그 아래 화면이면 ← (`navRoot`,
   `sidebar.tsx`). 뒤로 갈 곳은 그 메뉴 화면.
5. **공지 띠는 틀 안에서 접는다.** 검은 띠가 맨 위에 있으면 무엇을 해도 웹 배너다.
6. **긴 폼은 한 장이고, 길잡이는 고정한다.** 단계 마법사(이전·다음)를 쓰지 않는다.
   뒤 단계가 숨으면 확인하러 되돌아가야 하고 엄지가 갈 단추가 셋이 된다. 구간
   칩(`JumpNav`, `.jump-nav`)은 위에(`top: 0`) 붙어 지나는 구간이 켜지고, 저장·발급은
   아래에(`.wo-actions`, `.sticky-actions`, `.inspection-form-actions`) 붙는다.
   딸려온 값(표준서의 위험성평가·체크리스트)은 채운 채 접는다(`.std-fold`).
   "이게 뭔가요?" 의 답은 언제나 확인 창과 같은 시트·카드다(`HelpDialog`). 부르는
   자리는 둘이다 — 한 줄로 물어야 하는 것은 글 단추(`variant="text"`, 예: "어떤
   작업이 PTW 대상인가요?"), 구간 머리나 라벨에 딸리는 짧은 안내는 그 자리에 붙는
   물음표(`variant="icon"` · `"inline"`). 어느 쪽이든 누르는 자리는 44px 이다.
   라벨 옆 물음표는 그림을 줄이되 44px 상자는 음수 여백으로 숨긴다
   (`.help-dialog-icon--inline`). 물음표를 라벨에서 떼어 폼 오른쪽 끝에 띄우지
   않는다 — 무엇에 대한 물음인지 사라지고 좁은 화면에서 잘린다.
7. **옆으로 미는 띠는 크기를 격리한다.** `contain: inline-size`. 내용 너비가 문서의
   최소 너비로 번지면 모바일 브라우저가 화면을 그 너비로 넓혀 축소해 버린다.
   띠 안의 현재 항목은 띠만 `scrollTo` 로 민다 — `scrollIntoView` 는 조상까지 민다.
8. **스크롤 영역의 위 여백은 padding 이 아니라 첫 자식의 margin.** padding 위로는
   고정 머리가 올라가지 못해 그 띠에 지나가는 내용이 비친다.

## 2. 색

토큰(`globals.css :root`)만 쓴다. 색 코드를 직접 적지 않는다.

| 역할 | 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- | --- |
| 주조 | `--brand` | `#0f5b3c` | 버튼, 링크, 현재 단계, 워드마크, 로그인 전 머리 배경 |
| 주조 진하게 | `--brand-strong` | `#0b482f` | hover, 강조 글자 |
| 주조 연하게 | `--brand-soft` / `--brand-softer` | `#e4efe8` / `#f1f7f3` | 선택된 칩·행, 아바타 |
| 보조 | `--accent` | `#f2b705` | 강조 단어, 로그인 전 시작 버튼, 공지 점 |
| 보조 연하게 | `--accent-soft` + `--accent-ink` | `#fcf1cf` + `#6b4e00` | 알림 상자, 이유 아이콘 타일, 혜택 칩, "준비 중" |
| 글자 | `--ink` ~ `--ink-5` | `#15201b` … | 본문 → 보조 → 흐림 순 |
| 배경 | `--bg` / `--surface` | `#f3f3ee` / `#fff` | 화면 바탕 / 카드·입력칸 |
| 선 | `--line` 계열 | `#e4e6e0` … | 테두리 |
| 상태 | `--ok`, `#b83a12` | | 완료 / 삭제·오류 (빨강은 파괴적 동작과 오류에만) |

규칙:
- **초록은 "여기를 누르면 앞으로 간다"**, 노랑은 **"여기를 봐라"**. 노랑으로 누르는
  버튼을 만드는 곳은 로그인 전 머리(초록 위) 한 곳뿐이다.
- 노랑 글자는 연노랑 바탕 위에 `--accent-ink` 로만. 흰 바탕에 노란 글자는 안 읽힌다.
- 빨강은 지우기·취소·오류에만. 미조치 건수처럼 "주의" 는 빨강 숫자 하나로 충분하다.
- 카드는 흰색, 바탕은 종이색. 이 대비가 구획을 나누므로 선을 더 긋지 않는다.
- **스크롤 영역(main)에는 위아래 padding 을 두지 않는다.** sticky 머리·띠는 padding
  안으로 들어가지 못해 그만큼 떠서 서고, 그 밑으로 내용이 지나간다. 위 여백은 첫
  자식의 margin, 아래 여백은 `::after` 조각이며 아래 띠가 있는 화면은 조각을 뺀다.
  모바일 e2e 가 스크롤 중 띠의 아래 끝이 화면 바닥과 같은지 잰다.
- **틀의 높이는 실제 보이는 영역이다.** `100dvh` 가 아니라 visualViewport 높이
  (`--app-h`, `viewport-height.tsx`). iOS 는 키보드를 내린 뒤 화면을 되돌리지 않는
  일이 있어, 그때 아래 단추 띠가 화면 중간에 뜬다. 키보드가 열린 동안에는 띠가
  키보드 바로 위에 온다.

## 3. 글꼴

- **글꼴은 하나, Pretendard (가변).** `--font-sans`. 제목도 굵기(700–900)로만 구분한다.
  영문 전용 글꼴을 따로 두지 않는다. — `layout.tsx`, `globals.css`
- 본문 14px, 보조 12–13px, 화면 제목 17px(상단바)·24px(넓은 화면), 로그인 전 h1 24–40px.
- 입력칸은 항상 16px 이상 (iOS 가 확대해 버린다).
- **입력칸은 플로팅 라벨 하나다.** 라벨이 칸 안에 흐리게 있다가, 누르거나 값이
  들어가면 작아져 윗선에 앉는다 (`FloatField` · `FloatTextarea` · `FloatSelect`,
  `components/ui/float-field.tsx`, `.float-field`). 위 라벨 줄이 없어 폼이 짧고,
  좁은 화면에서도 짧은 칸을 나란히 세울 수 있다(비상연락처 [이름] [휴대폰]).
  - 예시 문구는 `hint` — 라벨이 칸을 차지하므로 누른 뒤에만 흐리게 보인다.
    칸 아래 안내는 `note` (화면 읽기가 칸과 함께 읽는다).
  - 날짜·시간·고르기(select)는 칸 안에 늘 글자가 있어 라벨이 처음부터 올라가 있다.
  - 라벨은 한 줄이다. 넘치면 말줄임이 되니 짧게 쓰고, 묶음 이름은 구간 제목·legend 에
    맡긴다("비상연락처" 아래 "이름 1").
  - 날 `<input>`·`<textarea>`·`<select>` 는 쓰지 않는다. 체크박스·라디오·파일·숨김·
    검색칸만 예외. 그 밖에 꼭 필요하면 바로 위 줄에 `헌법 3장 예외: 이유` 를 적는다.
    기계가 검사한다.
- `word-break: keep-all` — 한국어는 어절 단위로 줄을 바꾼다. 긴 주소만 `anywhere`.
- 숫자는 `tabular-nums` (타일, 건수).

## 4. 형태와 크기

- 모서리 8 / 12 / 16px (`--radius-sm` / `--radius` / `--radius-lg`). 칩은 999px.
- **누르는 것은 44px** (최소 40px). 버튼·입력칸·탭·카드형 링크·도움말 ?·×.
  본문 속 글자 링크만 예외. 모바일 e2e 가 40px 미만을 잡는다 (`mobile-layout.spec.ts`).
- 체크박스·라디오는 그림이 작아도 **누르는 자리(라벨)를 44px** 로. 사람 고르기는 칩
  전체가 체크박스다 (`people-picker.tsx`).
- 좌우 여백 16px(좁은 화면). 띠·고정 바는 `-16px` 로 화면 끝까지 민다.
- 주된 행동은 채운 버튼 하나. 한 줄에 채운 버튼이 둘이면 잘못됐다.

## 5. 움직임과 피드백

- **누르면 즉시 반응.** 화면 이동은 전체화면 로고(`loading.tsx`, 자식 폴더마다 재수출),
  제출은 버튼 글자가 "저장 중…" 으로. 아무 신호 없는 대기는 없다.
  새 화면 폴더를 만들면 검사 항목: `find src/app -name page.tsx` 의 각 폴더에
  자식 폴더가 있으면 `loading.tsx` 가 있어야 한다 (8장 검증).
- **확인은 앱 안의 시트로** (`useConfirm`). 브라우저 `confirm()` 금지. 되돌리기
  어려운 동작(삭제·취소·폐기·퇴사)은 빨간 버튼, 나머지는 초록.
- **저장하면 온 곳으로 돌아간다.** 보기 화면에서 "고치기" 로 들어왔으면 저장 뒤
  그 보기 화면으로. 편집 화면에 "저장했습니다" 만 띄우고 머무는 것은 잘못이다.
  예외는 아직 쓰는 중인 초안의 임시저장 하나.
- **저장 후 못 고치는 것은 저장 전에 요약을 보여 준다** (점검 저장).
- 미저장 입력은 기기에 보관했다가 다시 열면 "이어서 작성 / 버리기" 를 묻는다.

## 6. 문구

- **사장님 시각에서, 당기게 쓴다.** 공개 화면(홈·가이드·진단·문의)은 파는 글이다.
  읽는 사람이 "이거 써야겠다" 가 되게 쓴다. 면책·책임 회피·단서("법적 책임을
  대신하지 않는다", "실제 인정은 별도 심사", "정확하지 않을 수 있다", "최종 판단은
  기관에 확인")는 쓰지 않는다. 출처가 필요하면 맨 아래 한 줄 "출처: …" 로 끝.
  약관·개인정보 동의 한 줄(로그인)은 예외.
- **명사형으로 끊는다.** 마케팅·안내 문구에서 "~합니다/~됩니다" 를 늘어놓지 않는다.
  `'시작 요금' 없는` 처럼 짧게. 설명은 한 줄.
- **없는 것은 없다고.** 가짜 데이터·예시 숫자를 두지 않는다. 아직 없는 기능은
  "준비 중" 표시를 달거나 빼지, 있는 척하지 않는다.
- 제목은 이동 경로의 마지막 조각과 같아야 한다(상단바가 그걸 보인다).
- 작업자 쪽은 **"구성원은 QR만 찍으면"** 이라고 쓴다. 작업자 링크·QR 은 회사에
  초대된 구성원에게만 나가므로 가입은 되어 있고 로그인 절차만 없다. "로그인 없이"
  라고 쓰면 가입도 없는 것처럼 읽힌다.
- 오류 문구는 무엇이 잘못됐고 무엇을 하면 되는지 한 문장씩.

## 7. 화면별 첫 화면

- **로그인 전:** 초록 머리(누구에게, 왜) + 시작·진단 버튼 + 이유 넷.
  - 이유는 카드 전체가 단추. 누르면 긴 설명이 창(`.reason-dialog`, 좁은 화면은
    아래 시트)으로 뜬다. 접기(`<details>`)는 쓰지 않는다 — 열리면 아래 카드가
    밀려 한 화면 규칙이 깨지고, 닫힌 채로는 카드 사이가 빈다. 아이콘(동전·방패·
    QR·지구)과 제목·한 줄 요약·혜택 칩은 카드에 늘 보인다. 좁은 화면은 카드 넷이
    남는 높이를 나눠 갖고(글자 크기는 넓은 화면과 같다), 넓은 화면은 2×2.
  - 로그인 전 홈은 파는 글이다. 면책·단서("법적 책임을 대신하지 않는다", 심사
    기관, 적용 업종 조건)는 쓰지 않는다. 그런 말은 약관·도움말의 자리다.
  - 넓은 화면의 머리 오른쪽에는 작업자 화면 모형(`.hero-phone`)을 둔다. 모형에는
    실제로 있는 화면(오늘 점검 목록·허가서 승인·QR)만 그리고, 아직 없는 기능(언어
    칩·게이지)은 그리지 않는다. 좁은 화면에서는 숨긴다.
- **관리자 홈:** 오늘 타일 한 줄(오늘 작업·TBM 미확인·미조치·초안) + 시작 버튼
  한 줄 + 예정·진행 목록.
- **작업자 홈:** 오늘 작업 카드(안에 TBM 확인·작업 중 점검) + 놓친 회차 한 줄 +
  다른 작업 보기. 숫자 타일 없음.
- **작업자 링크 화면(`/w`):** 오늘 회차부터, 홈 화면에 추가 안내 한 번.
- **공개 화면(로그인·가이드·진단·문의·온보딩):** 홈과 같은 상단바(`.topbar--public`).
  화면마다 머리가 다르면 다른 서비스로 보인다.
- **작업지시 작성·편집:** 한 장. 작업 정보(표준서 고르기 → 작업명·방법·조·PTW) →
  위험성평가 → 일정·인원 → 체크리스트. 따로 "발급" 구간은 없다 — 무엇을 하는지는
  발급 확인 창이 말한다. 표준서를 고르기 전에는 고르는 칸만 있다. "새 표준서
  만들기" 는 표준서가 없는 회사만 밖에, 하나라도 있으면 찾기 창 안에만 둔다. 표준서 모드에서
  위험성평가·체크리스트는 "n건이 채워졌습니다" 로 접힘, 간이평가는 펼침. 아래 고정
  바는 (초안이면 삭제) · 임시저장 · 지금 발급하기. 좁은 폰에서 삭제는 휴지통만.
  다른 관리자 검토는 폼 아래 접힘. 구성원 초대는 작업자 선택 창 안(새 탭).
  PTW 는 불필요·필요 단추 + "어떤 작업이 해당되나요?".
  폼 안의 설명은 한 줄이 넘으면 줄인다. 누르면 무엇이 되는지는 단추 이름과 확인
  창이 말한다.
- **발급된 지시서 상세:** 한 장. 제목 줄(조·장소 · 발급 시각) → 상태 4칸 → 오늘 회차
  카드(한 줄 + TBM 확인하기 · 작업 중 점검하기) → 구간 칩 → 작업 정보(작업방법·장소·
  기간·PTW·표준서) → 위험성평가 → 일정·인원(회차 목록) → 체크리스트 → QR·전달. 탭 없음.
  발급 직후엔 QR 구간으로 내려간다. 지시서 번호·버전·출력 시각·판단 기준 표·설명 문단은
  없다(출력물에만). 취소는 맨 아래 단추, 변경 이력은 접힘.
- **TBM 확인·작업 중 점검:** 입력만. 머리(작업명 · 회차 날짜·시간) → 위험요인 목록 →
  체크리스트 → 저장. 코멘트 칸은 부적합·해당없음일 때만. 기록·회차 목록·관리자 도구는
  "점검 기록" 화면에.
- **표준서 개정:** 승인된 판은 고치지 않는다. "개정 시작" 이 현재 판을 통째로 복사한
  초안을 만들고(단계 사진 참조까지), 초안을 고쳐 "승인" 하면 새 판이 된다. 상세는
  현재 판·작성 중 초안 띠·개정 이력(판마다 보기)을 보여 주고, 지시서 발급과 평가
  회차는 그때의 판 번호를 박는다 ("프레스 금형 교체 (2판)").
- **표준서 작성·수정:** 구간 머리 오른쪽마다 물음표(`HelpDialog` icon) → 무엇·
  어떻게·왜 세 줄(`section-help.tsx`). 판단 기준은 폼에 펼치지 않는다 — 위험요인
  카드의 수준 옆 물음표가 회사 기준을 보여 준다(지시서·평가 회차도 같다). 단계와
  체크리스트는 두 칸씩 미리 있고 빈칸에 예시가 있다. 체크리스트의 이름은
  "안전/품질 체크리스트". 목록의 확정된 표준서는 "확정됨".
- **위험성평가:** 맨 위 숫자 셋(올해 평가·조치 남은 위험요인·평가 필요 표준서) →
  평가가 필요한 표준서 → 평가 목록(전체·유효·조치 필요·만료). 평가 화면은 제목 →
  구분·실시일·유효·작성·승인 한 줄 → 표준서·지시서 링크 → 위험요인 카드(계획과
  실제 조치를 나란히) → 안전보건정보 → 판단 기준·참여자. 위험요인 입력은 세 폼
  (표준서 최초평가·평가 회차·지시서 간이평가)이 같은 카드(`RiskItemCard`)를 쓴다:
  위험요인 → 현재 안전조치 → 수준(상·중·하 단추) → 허용 여부(단추) → 감소대책,
  담당·예정일은 접힘 (3단계 판단법 표준 양식의 순서). 판단 기준은 폼에서 적지
  않는다. 회사 기준을 서버가 사본으로 남긴다. 조치 뒤에도 허용 불가면 추가 대책을
  적어야 하고 항목은 계속 "남은 조치" 다 (고시 제13조). 위험성평가 화면 맨 위는
  경영책임자 반기 점검 카드 — 이 반기 숫자와 서명 여부 (중처법 시행령 4조 3호).
  실시규정은 회사정보 > 위험성 판단 기준 아래에 있다.
- **통합자료실(공지사항·자료실):** 목록은 제목·한 줄 요약·작성자·날짜 한 행.
  글 화면은 문서다: 제목 → 작성자·날짜(오른쪽에 고치기) → 구분선 → 본문 (넓은
  화면 760px). 상단바에는 제목이 아니라 게시판 이름이 남는다 — 제목은 본문의
  일부이고, 어디에 있는지는 상단바가 말한다. 공지 팝업은 홈·작업자 링크 화면에 들어올 때 한
  번, 닫기가 첫 단추이고 "오늘 하루 / 7일간 안 보기" 는 기기가 기억한다. 팝업이
  두 개 이상이면 최신 것부터 하나씩. 푸시 켜기 안내는 유료 회사에만, 한 번 닫으면
  다시 띄우지 않는다.

## 8. 검증

- 모든 화면 변경은 `npm run lint`·`typecheck`·`build`, 그리고 일회성 PostgreSQL 로
  `npm run test:orders-ui` (데스크톱·모바일). 모바일 e2e 는 가로 넘침·40px 터치
  타깃·메뉴 서랍 포커스를 잡는다.
- 스크린샷으로 색과 배치를 눈으로 본다. 테스트가 통과해도 이상하면 이상한 것이다.
- **기계가 검사하는 항목** (`scripts/check-constitution.mjs`, `npm run lint` 와
  `npm run build` 앞에서 돈다): 자식 화면 폴더의 `loading.tsx`, 브라우저
  `confirm/alert/prompt`, 위에 뜨는 오류 띠(`form-error`), 기능 CSS 의 색 코드,
  공개 화면의 면책 문구, 상태 표시줄 색 세 곳 일치, Pretendard 외 글꼴, 날 입력칸. 어기면 lint 와 build 가 실패한다.
- **사람이 검사하는 항목**은 저장소 루트 `CLAUDE.md` 의 새 화면 체크리스트다.
  세션 시작 때 자동으로 읽힌다. 저장 후 복귀, 44px, 단추 글자 쪼개짐, 스크린샷.
- 규칙을 어긴 사고가 나면 그 규칙을 기계 검사로 옮길 수 있는지 먼저 본다. 문서에
  한 줄 더 적는 것은 두 번째 수단이다.

## 9. 하지 않는 것

- 하단 탭 바 (지금은 없다. 넣을 때 이 문서부터 고친다).
- 브라우저 `confirm`/`alert`, 문서 스크롤에 기대는 고정 요소, 색 코드 직접 쓰기,
  두 번째 글꼴, 노란 배경의 누르는 버튼(로그인 전 머리 제외), 흰 바탕의 노란 글자,
  가짜 데이터, 한 줄에 채운 버튼 둘.
- **오류를 위에 조용히 띄우는 띠.** 저장은 아래 띠에서 누르는데 오류가 맨 위에
  뜨면 아무 일도 없던 것처럼 보인다. 오류는 안내 창(`FormErrorDialog`)으로 띄운다.
  기계가 검사한다 (`className="form-error"` 금지).
