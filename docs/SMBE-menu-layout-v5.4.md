# SMBE 메뉴·기능·화면 레이아웃 정의 v5.4

- 작성일: 2026-09-18
- 기준 문서: SMBE 설계 정리 v5.4
- 목적: 첫 개발 범위의 메뉴 구조, 화면별 기능, 주요 입력·출력, 화면 배치를 정의한다.
- 핵심 경험: 상담·체험 신청 없이 로그인 후 직접 사용하여 **1시간 이내 첫 결과를 확인**한다. 이는 제품 설계 목표이며 실제 소요시간 보장 문구는 아니다.
- 첫 결과: 평가 작성 → 작업지시 발급 → QR·링크 전달 → 작업자 참여 시 TBM 결과 확인. 타인의 승인·가입을 기다리는 시간은 별도로 본다.
- 문서 구분: 업무 규칙은 원 설계 기준, 메뉴명·화면 배치·UI 수치는 본 문서의 제안이다. 원 설계에서 불명확한 권한·동작은 마지막 장에 확인사항으로 분리한다.
- 원 설계의 요금제, 복사 중심 운영, 기존 종이 평가 이관 제외를 유지한다. 사업장 평가 현황 확대·월간 평가 연결 방식은 새 확정사항으로 추가하지 않는다.

- v5.5 변경: 표준서 개정본(판) 화면 — 상세의 표준서 개정·초안 띠·개정 이력·지난 판 읽기, 개정 화면의 초안 저장 / 저장하고 확정, 지시서·평가의 판 표시. 화면 용어는 "확정". 승인 대기 탭 없음 (2026-09-24).
- v5.4 변경: 법률 가이드 4개 인원규모 구간과 회사 생성 시 초기 규모 입력·실제 활성 인원 구분 반영.
- v5.3 변경: 기존 레이아웃 v1.0에서 설계서와 버전 통일. 비로그인 법률 가이드·인정 준비도 진단·가입 연결과 홈 슬로건 반영.

## 1. 화면 설계 원칙

1. 홈은 큰 행동 버튼 중심으로 구성한다. 통계 그래프와 복잡한 표를 첫 화면에 배치하지 않는다.
2. PC에서는 전체 메뉴를 항상 찾을 수 있게 하고, 자주 하는 일은 홈에서 바로 시작한다.
3. 작업표준서와 위험성평가는 별개 문서·별개 메뉴로 유지한다. 표준서가 평가를 대체하지 않는다.
4. 지시서 작성 중 표준서·평가·PTW 정보를 이어서 처리한다. 같은 내용을 다른 메뉴에서 반복 입력하지 않는다.
5. 장소·템플릿 사전 설정과 과거 종이 문서 이관은 첫 사용 조건이 아니다.
6. 반복 작업은 기존 지시서를 복사하여 작업일·인원을 확인하고 다시 발급한다.
7. 무료·유료 제한은 기존 정책대로 노출한다. 권한이 없는 기능과 유료로 사용할 수 있는 기능을 구분한다.
8. 설명은 짧게, 필수 항목은 명확하게, 저장·발급 등 주요 버튼은 한 영역에 모은다.
9. 현재 상태와 다음 행동을 함께 보여준다. 예: “PTW 승인 대기 · 승인자 김OO”.
10. 업무 옆의 짧은 법령 안내와 별도로, 비로그인 공개 안전법 가이드·인정 준비도 진단을 제공한다. 결과까지 공개하고 실제 기록 작성에서 가입으로 연결한다.

### 2-1. PC 관리자 메뉴

좌측 사이드바 기준. 1차 메뉴는 최대 2단계까지만 펼친다. 목록·상세·작성은 별도 메뉴 항목으로 중복 노출하지 않는다.

| 순서 | 1차 메뉴 | 2차 메뉴 | 역할 | 기준 장 |
|---|---|---|---|---|
| 1 | 홈 | 없음 | 첫 행동과 오늘 처리할 일 | 1, 12 |
| 2 | 작업지시 | 작업지시 내역 / 위험작업허가(PTW) | 지시 작성·복사·발급, 허가 처리 | 7~9 |
| 3 | 작업표준서 | 없음 | 작업방법·체크리스트·판(개정본) 관리 | 5-1 |
| 4 | 위험성평가 | 평가 내역 / 사업장 평가 현황 / 평가 기준·실시규정 | 평가 작성·검토·조치, 회차 현황 | 5-2, 5-3, 6 |
| 5 | 안전점검 | 점검 기록 / 부적합 조치 / 주간 안전점검 회의 / 점검 모니터링(유료) | 현장 결과·누락·개선 확인 | 10 |
| 6 | 안전사고 | 없음 | 지시서 연계·별도 사고 등록 | 11 |
| 7 | 회사정보 | 인원관리 / 장소관리 | 초대·가입 승인·권한·장소 설정 | 4 |
| 8 | 이용·관리 | 요금제·결제 / 과금 내역 / 감사 로그 / 회사 탈퇴 | 구독·청구·이력·종료 | 1, 13 |

- 상단 계정 메뉴: 내 정보, 소속 정보, 본인 퇴사, 로그아웃.
- 안전점수: 홈의 작은 카드에서 상세 패널로 진입. 별도 1차 메뉴로 만들지 않는다.
- 내 PTW 승인 대기: PTW 메뉴의 기본 탭으로 제공. 홈의 할 일에서도 직접 연결한다.
- 가입 승인 대기: 인원관리의 탭으로 제공. 새로운 승인센터를 만들지 않는다.
- 표준서 승인 대기 탭은 없다 (관리자가 곧바로 확정). 작성 중인 개정 초안은 그 표준서 상세의 띠로 보인다.
- 템플릿: 작성 화면에서 선택하는 기능으로 제공. 별도 템플릿 관리 메뉴는 만들지 않는다.
- QR 출력·점검 보고서: 해당 지시서·점검 화면에서 제공. 별도 문서함은 추후 범위다.
- 요금제·결제는 원 설계 16장에도 향후 메뉴로 등장하지만, 1장에 확정된 결제·과금 기능을 제공하기 위해 이번 메뉴에 포함한다.

## 3. 공통 레이아웃

### 3-1. PC 기본 틀

| 영역 | 제안 크기·배치 | 구성 |
|---|---|---|
| 상단 헤더 | 높이 약 64px | SMBE 로고, 회사명, 무료/유료 표시, 계정 메뉴 |
| 좌측 메뉴 | 너비 약 224px | 1차 메뉴, 선택한 메뉴의 하위 메뉴 |
| 본문 상단 | 제목＋우측 주요 버튼 | 경로, 화면 제목, 한 줄 설명, 신규 작성 등 |
| 본문 | 홈 1,120px 내외 / 목록 가용폭 | 홈 큰 카드, 목록 표, 작성 폼 |
| 작성 하단 | 고정 버튼 영역 | 이전·임시저장·다음·발급 등 현재 단계 행동 |
| 상세 보조 영역 | 선택적으로 우측 280px | 연결 문서·승인 정보·이력 요약 |

- 흰 바탕, 명확한 글자 대비, 충분한 여백. 색상보다 상태 이름을 우선한다.
- 진행·완료·대기·부적합은 텍스트 배지를 함께 사용한다.
- 목록 행 클릭은 상세로, 행 우측 복사·승인 등의 버튼은 즉시 해당 행동으로 연결한다.
- 작은 수정·선택은 우측 패널, 긴 작성과 검토는 전체 페이지를 사용한다.

### 3-2. 모바일 기본 틀

- 한 열 카드 배치, 본문 16px 내외, 터치 버튼 높이 최소 48px 제안.
- 상단: **SMBE 워드마크**(사이드바가 접혀 있어 브랜드가 안 보였다), 메뉴 버튼, 알림·계정.
  뒤로가기와 화면 제목은 상단바가 아니라 본문 제목 옆에 둔다 (좁은 화면에서 상단바가 꽉 찬다).
  현재 위치(breadcrumb)는 좁은 화면에서 제목과 같은 말이므로 표시하지 않는다.
- 하단: 화면의 핵심 행동 1~2개를 고정한다.
- QR·링크로 진입한 경우 로그인 후 해당 작업으로 돌아온다. 홈으로 보내 다시 찾게 하지 않는다.
- 무료 현장 화면에서는 관리자용 표나 복잡한 전체 메뉴가 기본 화면을 차지하지 않는다.
- 사진 첨부를 제외한 기본 체크·저장은 무료에서도 중단 없이 가능하다.

**이동 중 표시:** App Router 는 서버 컴포넌트를 받아 와야 화면을 바꾸므로, 링크를 누르고 응답이
올 때까지 아무 일도 일어나지 않는다. `loading.tsx` 는 진입하는 세그먼트에 파일이 있을 때만 뜨고
없으면 정말 아무 표시가 없다. 그래서 **누른 그 버튼 안에서** 스피너를 돌리고 링크를 잠시
비활성화한다(`useLinkStatus`). 어디를 눌렀는지는 사용자가 이미 아니까, 화면을 통째로 덮는 것보다
그 자리에서 도는 편이 덜 거슬린다. 뒤로가기 버튼은 링크가 아니므로 `useTransition` 으로 같은
표시를 한다.

## 4. 시작 화면과 홈

### U-01. 우리 회사 안전법 가이드

**목적:** 영세 사업장 운영자가 우리 회사에 필요한 안전관리와 다음 행동을 빠르게 찾는다.

**배치:** 공개 헤더 → 제목·한 줄 소개 → 업종 선택 → 법률 기준 인원규모 4개 구간 선택 → 중대재해처벌법 / 산업안전보건법 카드 → 자주 묻는 질문 → 인정 준비도 진단 CTA.

**인원규모 선택:**

| 선택지 | 내부 코드 | 안내 기준 |
|---|---|---|
| 5인 미만 | `UNDER_5` | 상시근로자 1~4명 |
| 5인 이상 ~ 20인 미만 | `FROM_5_TO_19` | 상시근로자 5~19명 |
| 20인 이상 ~ 50인 미만 | `FROM_20_TO_49` | 상시근로자 20~49명 |
| 50인 이상 | `FROM_50` | 상시근로자 50명 이상 |

- 사용자가 구간을 선택하면 관련 법률 카드와 질문을 해당 구간 중심으로 갱신한다.
- 구간 선택만으로 법적 적용 여부를 확정하지 않고, 업종·상시근로자 산정·시행일 등 추가 조건을 본문에서 표시한다.
- 회사 생성 전 선택값은 세션에 보관한다. 회사 생성 후에는 회사 프로필의 초기 규모로 저장하되 실제 등록 인원과 별도로 표시한다.

- 법률 카드는 각각 적용 대상·핵심 의무·준비할 기록을 짧게 요약한다.
- 입력 없이도 일반 안내를 읽을 수 있고, 조건 선택 시 관련 내용을 좁혀준다.
- 인원 정보만으로 모든 의무를 확정하지 않는다. 추가 조건이 필요하면 해당 질문만 표시한다.
- 사업장 이름·전화번호·이메일을 입력해야 읽을 수 있는 구조는 사용하지 않는다.

### U-02. 법률·질문별 상세 안내

**PC 배치:** 상단 제목·적용 기준일·검토일 → 좌측 짧은 목차 / 중앙 본문 → 관련 질문·공식 출처 → 다음 행동.

**모바일 배치:** 제목·날짜 → 접이식 목차 → 본문 → 관련 행동 버튼.

**본문 순서:** 누구에게 적용 → 해야 할 일 → 필요한 기록 → 영세 사업장 예시 → 공식 근거.

- 현재 시행 내용과 시행 예정 변경을 별도 구획으로 표시한다.
- 출처는 해당 조문·공식 안내를 직접 연결한다. 검토일을 매일 자동으로 오늘 날짜로 바꾸지 않는다.
- CTA는 **우리 회사 안전관리 시작하기** / **인정 준비도 확인하기**. 관련 기능이 있을 때만 구체적인 작성 화면으로 연결한다.
- 법률명·질문별 고유 URL, 페이지 제목·설명, SSR/정적 본문을 제공한다.
- 이 문서는 화면 정의이며 최신 법률 해설 원문은 별도 검토 후 게시한다.

### U-03. 위험성평가 인정 준비도 진단

**배치:** 제목·간단 설명 → 단계 표시 → 질문 카드 → 이전 / 다음 → 결과 보기.

| 단계 | 기능 | 입력 방식 |
|---|---|---|
| 1. 신청대상 검토 | 업종·규모 등 대상 조건 확인 | 선택형, 필요한 조건만 추가 질문 |
| 2. 준비상태 점검 | 위험요인·참여·대책·이행·기록 확인 | 예 / 아니오 / 모르겠음, 문항별 짧은 예시 |
| 3. 결과 확인 | 대상 여부·부족한 항목·다음 행동 | U-04로 이동, 가입 요구 없음 |

- 한 화면에 질문 하나 또는 짧은 관련 묶음을 보여준다. 긴 체크리스트 표를 강요하지 않는다.
- 종이·엑셀로 실시·보관한 내용도 응답에 포함한다. 기존 자료 업로드를 요구하지 않는다.
- 뒤로 가도 응답을 유지하며, 모르면 선택하고 진행할 수 있다.
- 신청대상 밖이거나 판단이 어려워도 이유·공식 확인 경로를 보여준다. 대상 미해당을 '안전관리 불필요'로 표현하지 않는다.
- 실제 문항·대상 조건·판정 규칙은 공식 기준 검토 후 확정한다. 점수 산식은 이번 버전에서 확정하지 않는다.

### U-04. 자가진단 결과

**배치:** 신청대상 검토 결과 → 준비상태 요약 → 보완·확인 항목별 카드 → 구체적인 다음 행동 → 짧은 심사 안내.

| 영역 | 표시 | 행동 |
|---|---|---|
| 신청대상 | 응답상 대상 조건 부합 / 대상 조건 미부합 / 추가 확인 필요 | 기준 설명·공식 안내 |
| 준비상태 | 항목별 충족 / 보완 필요 / 확인 필요 | 응답 수정·이유 펼치기 |
| 다음 행동 | 부족한 항목과 준비 방법 | 무료로 평가 작성 시작하기 등 |
| 안내 | 사용자 응답 기준이며 실제 인정은 공단 별도 심사 | 공식 신청 절차 보기 |

- 모든 결과는 비로그인으로 열람 가능. 회원가입으로 결과를 가리지 않는다.
- '인정 확정', '합격률', 미확정 총점·인정 기준선은 표시하지 않는다.
- 예시 CTA: **위험요인 확인과 개선조치 기록이 필요해요 → 무료로 평가 작성 시작하기**.
- SMBE에 없는 기능은 준비 방법과 공식 경로를 안내한다.
- 결과·응답은 검색 노출하지 않는다. 결과 URL에 답변을 포함하지 않고 타인의 결과를 열람하는 기능도 두지 않는다.
- 답변이 없거나 임시 보관이 끝났다면 결과를 추정하지 않고 **다시 진단하기**를 제공한다.

### U-05. 진단에서 가입·작성으로 이어가기

**흐름:** U-04에서 행동 선택 → A-01 로그인 → 회사 생성·연결 → 선택한 작성 화면.

- 업종·인원규모 구간·답변·선택 행동은 같은 브라우저 세션에 임시 보관한다. 브라우저를 닫거나 다른 기기로 이동할 때의 복구는 초기 범위에 넣지 않는다.
- 로그인 실패 시 재시도하며 입력을 유지한다. 이어갈 정보가 없으면 일반 시작 흐름으로 진행한다.
- 회사 생성 시 입력한 업종·인원규모 구간을 미리 채우되 사용자가 확인·수정한다. 진단 인원과 실제 등록·과금 인원은 별개다.
- 기존 소속이 있으면 권한 확인 후 관련 화면으로, 가입 승인대기이면 해당 안내 후 이어갈 행동을 유지한다.
- 자가진단 답변을 실제 평가·개선조치 완료 기록으로 변환하지 않는다. 업무 화면에서 실제 내용을 작성·확인한다.
- 로그인 없이 공개 안내를 보는 것과 회사 업무 API를 이용하는 것의 인증 경계를 유지한다.

### A-01. 로그인·회사 연결

**기능:** 네이버·구글·카카오 로그인, 회사 생성, 회사코드 가입, 초대 링크 가입, 승인 대기 안내.

**배치:** 중앙 로그인 카드 → 소속 없는 경우 ‘회사 만들기 / 회사코드로 참여’ 두 카드. 초대 링크 진입은 회사명을 보여주고 해당 회사 참여 흐름으로 연결.

**회사 생성:** 회사명(UI 제안), 업종, **초기 인원규모 구간(5인 미만 / 5~19인 / 20~49인 / 50인 이상)** 등 필요한 기본값 중심. 생성자는 관리감독자 권한을 갖는다. 장소 계층·표준서 등록·기존 종이 평가 업로드를 선행 단계로 요구하지 않는다.

- 생성 시 선택한 구간은 `company.initial_employee_size_band`로 저장한다.
- 회사 업무 화면에는 `initial_employee_size_band`, 등록된 `active_headcount`, 자동 산출한 `current_employee_size_band`를 구분해 표시한다.
- 실제 인원 구간은 활성 인원 등록·퇴사 처리 때 자동 계산한다. 초기 선택값이 실제 인원과 다르면 안내만 하고, 사용자가 임의로 과금·권한을 바꾸게 하지 않는다.

**상태:** 소속 없음 → 회사 선택 / 가입 승인대기 → 대기 안내 / 가입 완료 → 홈. 초대 링크는 별도 가입 승인 없이 소속 처리한다. 휴대폰 인증은 추가하지 않는다.

### H-00. 로그인 전 홈 (공개)

**목적:** 무엇을 하는 서비스인지 알리고 시작·진단으로 보낸다.

**배치:** 히어로 → 카드 둘([무료로 시작하기] `/login` · [우리 회사는 준비됐나] `/recognition-check`)
→ "무엇을 하는 서비스인가" 4칸(표준서·위험성평가 / 작업지시·QR / TBM·점검 / 주간 회의)
→ 요금 한 줄과 문의 링크.

- **가짜 데이터를 두지 않는다.** 전에는 "오늘 처리할 일 3건", "제1공장 프레스 설비 점검" 같은
  예시 목록을 깔고 누르면 준비 중 안내를 띄웠다. 처음 온 사람에게는 이미 돌아가는 회사의
  화면처럼 보이고, 눌러도 아무 일이 없어 신뢰를 깎는다. 숫자·목록 대신 **실제로 하는 일**만 적는다.
- 준비 중 안내 대화상자는 아직 없는 기능(상단바 알림, 사이드바의 미구현 메뉴)에만 남긴다.
- 로그인 사용자 홈(H-01)과는 다른 화면이다. 같은 컴포넌트가 `isAuthenticated` 로 갈린다.

### H-01. 관리자 홈 (로그인 후)

**목적:** 처음 온 사장이 메뉴를 공부하지 않고 첫 작업을 시작한다.

| 위→아래 | 화면 내용 | 행동 |
|---|---|---|
| 1 | **Safety must be easy.** / 안전관리, 쉽고 간편하게 시작하세요. | easy.를 주황색 강조, 회사명·요금제는 헤더 |
| 2 | 가장 큰 카드 두 개: **작업자·관리자 초대하기 / 오늘의 작업 지시하기** | 초대 패널 / 작성 페이지 |
| 3 | 평가 시작·이어쓰기 안내 카드 | 표준서 연계 평가 또는 간이평가로 이동 |
| 4 | 내가 처리할 안전조치(미조치 부적합) — **있을 때만** | 안전점검 화면으로 이동 |
| 5 | 오늘 작업 카드 3~5개＋전체 보기 | 지시서 확인, 기존 작업 복사 |
| 6 | 작은 안전점수 카드 | 상세 패널 열기 |

- 최초 홈은 2번의 두 버튼이 가장 눈에 띄게 한다. 아래 영역은 자료가 있을 때 필요한 만큼 노출한다.
- 첫 지시서가 없을 때 ‘오늘 작업 없음’이라는 큰 빈 표를 만들지 않는다.
- 평가 카드에는 ‘앞으로 실시하는 평가를 SMBE에서 관리하세요’를 사용한다. 시스템 기록이 없다는 이유로 법정 미실시를 확정하지 않는다.
- 반복 이용 시 오늘 작업 카드에서 **[복사해서 지시하기]**를 바로 제공한다.
- 전체 회사의 이행률 그래프·모니터링은 유료 메뉴에 둔다.
- 작업자 홈은 이 구성을 사용하지 않고 나에게 배정된 작업과 TBM 버튼을 중심으로 한다.

### H-02. 안전점수 상세 패널

**기능:** 자체 점수, 항목별 현황, 개선할 행동, 인정제도 안내.

**배치:** 상단 점수와 자체 진단 표기 → 항목별 접이식 목록 → 관련 기능으로 이동 버튼 → 인정제도 설명.

**규칙:** 공개 U-03/U-04는 자가응답 기반, 이 패널은 회사 업무 데이터 기반이다. 공개 진단 응답으로 회사 안전점수를 자동 갱신하지 않는다. 인정제도 설명에서 공개 가이드·준비도 진단으로 연결한다. 무료도 전체 제공. 점수 산식·배점·인정 기준선 표현은 추후 재검토 대상이므로 이 문서에서 확정하지 않는다. 미완성 산식을 실제 점수처럼 표시하지 않는다. 안전방침·교육 이수 등 원 설계에서 입력 화면이 없는 항목은 확인사항으로 둔다.

## 5. 작업지시 메뉴

### W-01. 작업지시 내역

**기능:** 조회, 신규 작성, 복사, 취소, QR 출력, 사고 등록 진입.

**배치:** 제목＋[작업 지시하기] → 상태 탭 → 작업명 검색 → 목록 → 페이지 이동.

**목록 열:** 작업명(+평가 승인 상태), 기간·시간, 장소, 배정 인원, 지시서 상태.

**좁은 화면에서는 표를 카드로 접는다.** 한 행이 다섯 칸이라 가로 스크롤로는 한 건도 온전히
보이지 않았다. 헤더를 숨기고 각 칸 앞에 이름표(`data-label`)를 붙이며, **카드 전체가 눌린다**
— 제목만 링크면 손가락으로 찾아 눌러야 한다. 넓은 화면은 표 그대로 둔다. 줄을 여러 개
훑을 때는 칸이 정렬된 표가 낫다.

**기본 탭:** 오늘·진행 중 / 작성 중 / 발급대기 / 전체. 작업자에게는 배정된 작업만 노출한다.

**무료:** 지난 기록은 최근 1주일만 상세 열람. 발급·진행 중 지시서는 기간 제한에서 제외. 오래된 기록의 우회 상세 접근도 제한한다.

**초안 삭제:** 작성 중(DRAFT) 초안만 지운다. 발급된 지시서는 삭제 대상이 아니다 — 법정 기록이고
회차·점검·부적합이 딸려 있어 지우면 증빙에 구멍이 난다. 그 경우의 수단은 **취소**다. **목록의 그 줄에서 바로 지운다** — 잘못 만든 초안이 여러 개 쌓였을 때 하나씩 상세로
들어갔다 나오게 만들 이유가 없다. 지시서 상세의 액션 줄(목록·편집·복사 옆)에도 같은 버튼을
둔다. 발급 뒤에는 이 버튼이 사라지고 [지시서 취소]만 남는다(둘이 동시에 보이지 않는다).
행은 지우지 않고 감춘다(`deleted_at`) — 초안에도 간이평가·배정이 딸려 있어 물리 삭제하면
정리할 것이 줄줄이 나오고 되돌릴 방법이 없어진다. 누가 언제 지웠는지는 감사 로그에 남는다.

### W-02. 작업지시 작성·복사

**배치:** 상단 진행 단계 → 중앙 폼 → 우측 작업 요약(PC) → 하단 저장·다음 행동.

| 단계 | 화면 내용 | 핵심 동작 |
|---|---|---|
| 1. 작업 선택 | 기존 표준서 / 표준서 없이 시작 | 표준서 기반은 최신 승인 평가를 연결. 없으면 작성·승인으로 이어서 복귀 |
| 2. 위험 확인 | 평가 요약 또는 간이평가 폼, TBM·작업 중 체크리스트 | 표준서 없는 경우 업종 템플릿을 채워서 열기 |
| 3. 일정·인원 | 작업기간, 시작·종료시간, 장소, 작업자 배정, 조 추가 | 장소 직접입력, 인원 초대 경로 제공, 조별 지시서 분리 |
| 4. 허가·발급 | PTW 필요 여부, 필요한 허가 정보, 최종 요약 | 바로 발급 / 허가 신청 후 발급대기 / 본인 신청&승인 |

- 복사는 동일 폼에 기존 정보를 채운다. 작업일, 상태, 발급·승인·점검 이력은 초기화한다.
- 배정 인원은 복사하되 해제 가능. 표준서를 고르면 그 판 번호("n판")가 보이고 그 순간 지시서에 판이 붙는다. 복사본은 원본이 복사한 판을 유지한다 (개정 자동 반영은 미구현).
- 원본 표준서 폐기 시 복사 불가. 간이평가 기반은 해당 내용을 복사한다.
- 표준서에서 온 체크리스트는 삭제 불가, 현장 항목 추가 가능.
- 작업시간 상한 16시간. 주·야간조는 조 추가로 별도 지시서를 만든다.
- 인원 초대·표준서 작성으로 이동해도 작성 중인 지시 내용을 유지한다.
- 지시서 자체에 별도 승인 단계를 추가하지 않는다. 평가 승인과 PTW 승인은 각 문서 규칙을 따른다.
- 간이평가의 빠른 승인 UI는 원 설계에서 상세 미정이므로 17장 확인사항으로 남긴다.

### W-03. 지시서 상세

| 영역 | 내용 |
|---|---|
| 상단 제목 | 작업명, 발행 버전, 작업기간·장소 |
| 독립 상태 4개 | 작업 일정 / PTW(필요 시) / 오늘 TBM / 미조치 부적합 |
| 주요 버튼 | 역할·상태별 복사, 일정·인원 변경, 사고발생, 취소 |
| 본문 탭 | **작성 단계와 같은 번호** — 1 작업 정보 / 2 위험성평가 / 3 일정·인원 / 4 체크리스트 / **5 QR·전달** |
| 보조 영역 | 작성자, 연결 표준서와 그 판(예: "프레스 금형 교체 (2판)" — 지난 판이면 그 판 화면으로 링크하고 "표준서는 그 뒤 3판으로 개정됨" 표시), 평가, 승인 정보 |

- 탭을 작성 폼과 같은 번호로 맞춘다. "3번에 뭘 넣었더라"를 같은 자리에서 찾게 하려는 것이다.
  발급 전에는 4개, **발급되면 5번 QR·전달 탭이 생긴다.** 없는 QR 자리를 미리 만들지 않는다.
- **발급 직후에는 5번 탭으로 바로 보낸다.** 그 순간 할 일은 QR 을 뽑아 붙이거나 링크를 보내는
  것인데, 한 장짜리 문서에서는 그게 스크롤 맨 아래에 있었다.
- 5번 탭: QR 이미지, 지시서 URL, 링크 복사, 배정 인원별 전달 상태, 미전달 재발송, **인쇄 버튼**.
- **인쇄물은 화면 문서 전체가 아니라 현장 게시용 A4 한 장이다.** 작업명·기간·장소·PTW·배정
  인원·위험요인과 대책·TBM/작업 중 체크리스트·QR 을 담는다. 어느 탭을 보고 있든 같은 한 장이
  나간다. 인쇄 창에서 대상을 'PDF로 저장'으로 바꾸면 PDF 파일이 된다.
- **출력은 유료 기능이다.** 무료 회사는 버튼을 숨기지 않고 눌렀을 때 안내로 막는다 — 버튼이
  없으면 "이 제품에는 출력이 없다"로 읽히지만, 안내가 뜨면 무엇을 얻는지 알고 결정할 수 있다.
- 탭은 URL(`?tab=`)에 남는다. 새로고침·뒤로가기·링크 공유가 그대로 동작해야 한다.
- **작업자에게는 탭을 쓰지 않는다.** 작업자에게 필요한 건 다섯 개의 탭이 아니라
  [TBM 확인하기] [작업 중 점검하기] 두 개다. 한 장으로 펼쳐서 보여준다.
- 상태 4칸·회차 요약·지시서 취소·변경 이력은 탭 밖에 둔다. 어느 탭에 있든 보여야 판단이 되고,
  취소는 탭 안에 숨기면 오히려 위험하다.
- 평가·체크리스트는 지시서 발행 당시 스냅샷을 보여준다. 현재 마스터 정보로 조용히 덮어쓰지 않는다.
- COMPLETED는 작업기간 종료다. ‘작업기간 종료 · 미조치 2건’처럼 표시하며 부적합을 종결시키지 않는다.
- 작업자가 보는 주요 버튼은 **[TBM 확인하기] [작업 중 점검하기]**. 관리자 편집 버튼은 숨긴다.
- 당시 배정 인원·점검 내역과 현재 배정 인원을 구분하여 과거 이력을 확인할 수 있게 한다.
- 출력 후 변경됐으면 모바일 작업 상세와 점검 시작 화면에 변경 표시.

### W-04. 일정·인원 변경 패널

**배치:** 변경 전 정보 → 새 일정·인원 → 승인 필요 여부 안내 → 변경 버튼.

- PTW 있음: 일정 변경은 승인 후 반영, 인원 추가는 승인 대기 중에도 배정되어 점검 가능.
- 인원 제외는 즉시 반영. 추가 반려 시 배정 해제, 이미 남은 기록 보존.
- 본인이 PTW 승인자이거나 PTW 없는 지시서는 설계상 승인 생략 규칙 적용.
- 작업 없는 날은 일정에서 제외하여 해당 회차를 만들지 않는다.
- 장소·작업 내용·체크리스트 등 변경은 취소 후 재발행으로 안내한다.

### W-05. 발급 결과·QR 출력

**구현:** 별도 화면을 두지 않고 지시서 상세의 **5번 QR·전달 탭**이 이 역할을 한다.
발급하면 그 탭으로 바로 이동한다 (W-03 참조).

**배치:** QR 이미지 → 지시서 URL → 인쇄 버튼 → 링크 복사 → 배정 인원별 전달 상태 → 재발송.

- 발급대기이면 완료로 표현하지 않고 지정 승인자와 현재 상태 표시.
- **출력은 유료 기능이다** (v5.8에서 전환). 무료는 버튼을 눌렀을 때 안내로 막고, 화면의 QR 과
  이메일 링크로 전달하게 한다. 점검 결과 보고서와는 다른 출력 기능이다.
- 출력물은 **A4 한 장**이며 작업 정보, 위험요인·대책, 체크리스트, QR, 발행 버전·출력일시를 담는다.
- 링크 발송 실패 시 실패 상태를 표시하고 재전달 동선을 제안한다. 재발송 상세 정책은 UI 구현 시 결정.

## 6. 위험작업허가(PTW)

### P-01. 허가 목록·내 승인 대기

**배치:** 내 승인 대기 / 전체 허가 탭 → 작업기간·상태·신청자·자가 승인 필터 → 허가 목록.

**목록 열:** 작업명, 장소, 허가기간, 신청자, 승인자, 상태, 자가 승인 표시.

**동작:** 승인 대기는 작업 시작일 순 정렬, 임박·기한 경과 표시, 선택 일괄 승인. 기한이 지났거나 본인에게 지정되지 않은 건은 승인 대상으로 선택할 수 없다.

**작성 진입:** [허가가 필요한 작업 지시하기] → W-02. 독립 허가 문서를 새로 작성하는 흐름을 만들지 않는다.

### P-02. 허가 상세·승인

**배치:** 상단 허가 상태·유효기간 → 작업지시 연동 정보 → 화기작업 등 허가 항목 → 승인 이력 → 하단 승인/반려.

**항목:** 신청자·승인자·승인일시, 장소, 설비, 작업 내용, 책임자, 인원, 특이사항, 화기작업·화재감시자, 비상연락처 다건.

- 본인에게 지정된 승인대기 건만 승인·반려. 반려 사유 필수.
- 신청자는 대기 중 철회·승인자 변경 가능. 이력과 알림 연결.
- 본인 승인 선택 시 ‘신청&승인’, 처리 후 자가 승인 태그 표시.
- 지시서 최초 발급 전 승인 완료 → 자동 발급. 별도 발급 버튼을 다시 누르게 하지 않는다.
- 발급 후 추가 PTW 미승인 상태는 지시서·TBM에서도 표시하지만 기존 정책대로 작업·점검을 차단하지 않는다.
- PTW 전용 사전점검표나 허가 종료 버튼은 추가하지 않는다.
- PTW는 기간 만료로 만료 처리. 지시서 취소 시 무효.

## 7. 작업표준서

### S-01. 표준서 목록

**배치:** 제목＋[표준서 만들기] → 전체 / 사용 중 / 작성 중 / 폐기 탭 → 검색 → 목록.

**목록 열:** 작업명, 사용 가능 여부(평가 만료면 "정기평가 필요"), PTW 필요 여부, 승인 평가 수, 최근 평가일, 수정일. 판 번호는 상세에서 본다.

**동작:** 상세, 권한 내 폐기. 작성·개정·확정은 관리자만 (작업자는 표준서 메뉴에 들어오지 않는다). 승인 대기 탭은 없다.

### S-02. 표준서 작성·개정

**작성(신규):** 상단 구간 이동 탭 → 작업명·작업 단계 → PTW 필요 여부 → 작업 전/작업 중 체크리스트 → 최초 위험성평가 → 저장. 저장하면 곧 **1판**으로 확정되고 상세로 돌아간다 (단추 "표준서 저장 · 확정").

**개정:** 상세의 [표준서 개정] 이 확인 창("{표준서명} 표준서의 개정본을 만드시겠습니까? …") 뒤 현재 판을 복사한 초안을 만들고 이 화면을 연다 (`/standards/[id]/edit`). 초안이 없으면 상세로 보낸다.

- 제목은 "n판 개정". 상단에 **개정 사유** 구간 (선택, 확정 때 이력에 남는다).
- 작업 단계는 순서대로 편집하고 단계마다 사진을 붙이거나 지운다 (유료). **사진 편집은 초안에서만** — 확정된 판의 사진은 상세에서 읽기만 된다.
- 하단 두 단추: **초안 저장**(상세로 돌아오고 현재 판은 그대로) / **저장하고 확정**(초안 → 현재 판, 이전 판 → 지난 판).
- 작업 단계가 하나도 없으면 승인되지 않는다.

### S-03. 표준서 상세

**배치:** 작업명 · "n판 · 확정 날짜 · 확정자" · 상태 → (초안이 있으면) **초안 띠**: "m판 개정 작성 중 · 작성자 · 날짜" 와 [이어서 수정] [이대로 확정] [버리기] → 작업 단계(사진 읽기) / 안전·품질 체크리스트 / 연결 위험성평가(현재 사용 중 위험성평가 — 판단 기준 표는 여기서 보이지 않는다, 회차 이력) / **개정 이력 (n판)**: 판마다 상태·확정일·확정자·사유와 [보기].

**버튼:** 첫 줄 [이 표준서로 지시서 작성], 둘째 줄 [표준서 개정](초안이 없을 때) [위험성평가 회차 추가] [폐기]. 승인·반려 단추는 없다.

- 평가가 없으면 '평가 이어서 작성' 안내. 해당 표준서로 지시서 발급은 평가 승인 후 가능.
- 폐기는 관리자. 작성 중인 초안이 있으면 "먼저 초안을 버리거나 확정한 뒤 폐기하세요" 로 막는다. 폐기된 표준서는 개정할 수 없다. 이전 판 조회와 현재 사용 판을 구분한다.
- **지난 판 읽기** (`/standards/[id]/revisions/[no]`): 그 판의 작업명·PTW·단계·사진·체크리스트를 읽기만 한다. 지시서·평가가 가리키는 "그날의 표준서" 가 이것이다.
- 표준서 상세의 평가 탭은 연결 문서를 보여주는 영역이며 문서 자체를 하나로 합치지 않는다.

## 8. 위험성평가

### R-01. 평가 내역

**기능:** 등록된 평가 검색·상세·작성·승인·조치 확인.

**배치:** 제목＋[평가 작성] → 실시 구분·기간·상태·작업명 필터 → 평가 목록.

**목록 열:** 평가명/작업명, 최초·정기·수시·상시, 표준서(상세에서 "n판")또는 ‘간이평가’, 실시일, 작성자, 승인 상태, 조치 현황.

- 공통 데이터 구조에 저장한 간이평가도 원문에 접근할 수 있게 한다. 이는 개별 평가 내역 조회 UI 제안이며, 5-3 사업장 회차 집계·미평가 판정 범위의 확대를 뜻하지 않는다.
- 기존 종이 평가를 업로드하거나 과거 기록을 재입력하는 필수 화면을 만들지 않는다.
- 평가 원문 조회에 작업지시·점검의 1주일 제한을 자동 적용하지 않는다.

### R-02. 일반 평가 작성·간이평가 공통 폼

| 순서 | 영역 | 입력·표시 |
|---|---|---|
| 1 | 기본정보 | 작업명·대상, 실시 구분·일자, 연결 표준서와 그 판(간이평가는 없음) |
| 2 | 안전보건정보 | 작업방법, 설비, 물질, 주변 환경, 재해·아차사고 정보 |
| 3 | 위험성 판단 기준 | 회사 기본 기준, 허용 수준 확인 |
| 4 | 위험요인·대책 | 위험요인, 현재 안전조치, 수준(상·중·하 단추), 허용 여부(수준과 회사 기준에서 자동 판정, 글 한 줄), 감소대책, 조치 필요 시 담당자·예정일 |
| 5 | 참여·검토 | 참여 근로자, 작성자·승인자 |
| 6 | 저장·승인 | 필수값 확인, 저장·승인 처리, 지시서로 복귀 |

**배치:** 긴 표 하나 대신 위험요인별 접이식 카드. PC에서는 각 카드 안에서 항목을 가로 배열하고 모바일 유료에서는 세로 배열한다. 사용자가 현재 편집 중인 카드만 펼칠 수 있게 한다.

**간이평가:** 업종 템플릿 자동 적용, 기본값 확인·수정, 불필요한 위험요인 삭제 가능. 단순화는 입력 방식을 뜻하며 필수 평가 기록은 유지한다.

**진입 차이:** 표준서에서 시작하면 작업방법·버전을 가져온다. 지시서에서 시작하면 입력한 작업명 등을 유지하고 저장 후 같은 지시서 단계로 돌아온다.

### R-03. 평가 상세·조치 이행

**배치:** 평가 개요·상태 → 위험요인별 판단·대책 → 참여자 → 조치 이행 → 연결 지시서·기록 이력.

- 조치 항목별 실제 내용, 완료일, 조치 후 위험성 수준·허용 여부를 입력·확인한다.
- 계획과 실제 이행을 별도로 보여준다. 평가 승인만으로 조치완료 처리하지 않는다.
- 조치 담당자가 입력할 수 있는 범위와 평가 승인 권한은 원 설계에서 상세 확정이 필요하다.
- 지시서에 이미 사용된 평가 스냅샷과 현재 평가의 후속 조치 정보를 구분한다.

### R-04. 사업장 평가 현황

**기능:** 원 설계 5-3의 평가 회차 생성, 기간 기준 자동 수집, 등록 표준서 기준 미평가 작업 확인, 회차 승인·유료 출력.

**배치:** 좌측 회차 목록(PC 25%)＋우측 선택 회차 상세(75%). 모바일 유료에서는 회차 목록→상세로 분리.

**상세:** 회차명·구분·기간 → 평가된 작업 / 미평가 작업 탭 → 개별 평가 링크 → 회차 승인·보고서.

- 최초 진입: [평가 회차 만들기], 이름·구분·기간 입력.
- 자동 수집은 원 설계 범위 유지. 장소·설비 전체 평가대장 확장은 넣지 않는다.
- 기간 중첩 시 어떤 회차에 배정하는지는 확인사항으로 둔다.

### R-05. 평가 기준·실시규정

**배치:** 위험성 판단 기준 / 실시규정 탭.

- 판단 기준: 상·중·하 기본값, 각 수준 설명, 허용 가능한 수준, 기준 결정·변경에 참여한 근로자.
- 실시규정: 기본 템플릿 불러오기, 목적·방법·역할·시기 편집, 저장.
- 첫 지시서 작성에서 설정 페이지로 강제 이동하지 않는다. 기본값 확인은 공통 폼 안에서 이어가도록 제안한다.
- 수정 권한은 관리자 기준 제안이며 원 설계의 명시적 권한 보완이 필요하다.

## 9. 안전점검

### I-01. 점검 기록

**기능:** 회차별 TBM·작업 중 결과, 역할별 조회, 누락 확인, 관리자 사후입력·수정, 유료 보고서.

**구현:** 목록은 `/inspections`, 회차 상세·입력·수정은 `/work-orders/<id>/inspections?session=<id>`.
목록에서 회차를 누르면 그 회차가 열린 상세로 간다. 기록 렌더링을 두 번 만들지 않기 위해
상세 화면을 재사용한다.

**배치(목록):** 기간·작업명·상태 필터 → 회차 목록. **회차가 행이다** — 이 화면의 목적은
누락을 찾는 것이고, 점검 구분·역할·결과별 상세는 회차를 열어서 본다.

**목록 열:** 작업일자, 작업명, 회차 시간, TBM 확인 인원, 작업 중 점검 건수, 이행 완료·미이행,
부적합 수(미조치 별도), 사후 입력 건수.

**상태 필터:** 전체 / 누락 회차만 / 완료 회차만 / 미조치 부적합 있음 / 사후 입력 포함.
집계 결과에 걸리는 조건이라 SQL 뒤에서 거른다.

- TBM은 전원 확인, 작업 중 점검 완료 기준은 회차당 1건 이상.
- 점검 완료 여부와 부적합 조치완료 여부는 별도 표시.
- 사후입력은 실제 입력일시·입력자·경로를 남긴다. 과거 현장 입력으로 보이게 하지 않는다.
  기록 목록에서는 **펼치지 않아도** 사후 입력 표식이 보인다 — 훑는 사람이 현장 입력과
  구분하지 못하면 표시한 의미가 없다.
- 입력 패널: 누구의 점검인가 → 점검 구분 → 항목별 결과·코멘트 → 저장. 배정되지 않은
  작업자의 기록은 만들 수 없고, 관리자는 순회점검으로 참여할 수 있으므로 배정과 무관하다.
- 수정 패널: 각 기록 안의 접이식 [결과 수정]. **사유가 필수**이고 수정 전·후가 통째로 남는다.
  이미 조치완료된 부적합은 되돌릴 수 없다 — 조치 내용과 담당자 기록까지 사라지기 때문이다.
- 수정 이력은 작업지시별로 한곳에 모아 보여준다 (누가·언제·왜·무엇이 어떻게 바뀌었는지).
- 무료는 최근 1주일 기록. 그보다 오래된 회차는 목록에서 빠지고 **건수만** 남는다.

### I-02. 부적합 조치

**범위:** 점검에서 생성된 부적합 관리. 원 설계 16장의 모든 제보·사고·대책 통합 개선조치 플랫폼으로 확대하지 않는다.

**배치:** 내 담당 조치대기 / 전체 / 조치완료 탭 → 작업·발생일 필터 → 목록 → 조치 패널.

**목록 열:** 발생일, 작업명, 점검 항목, 내용, 담당 관리자, 조치 상태, 완료일.

**조치 패널:** 부적합 원문·허용된 사진 → 담당자 → 조치 내용 입력 → [조치완료]. 별도 확인자 승인 없음.

- 조치 권한은 선택된 담당 관리자 기준. 다른 관리자에게 자동으로 종결 권한을 확대하지 않는다.
- 조치 내용은 다음 회차 TBM에서 보여준다.
- 작업기간 종료와 독립하여 OPEN 유지.
- 조치 기한·독촉 정책은 원 설계 미정. 임의로 기한 초과 경고를 만들지 않는다.
- 과거 점검 열람 제한과 아직 열린 부적합 처리의 관계는 출시 전 확인사항이다.

### I-03. 주간 안전점검 회의

**구현:** 목록은 `/meetings`, 회의는 `/meetings/<월요일 날짜>`. 사이드바 안전점검 하위에
'점검 기록'과 나란히 둔다.

**배치(목록):** 이번 달 집계 → 최근 12주 목록. 주마다 실시 완료 / 작성 중 / **미실시** 를
표시하고, 미실시 주에는 [회의 열기] 버튼이 붙는다.

**배치(회의):** 수집 항목 → 항목별 이행 확인·비고 → 참석자·논의 내용 → [회의 완료].

**주 단위:** 한국시간 **월요일 시작**. 회차(작업일자)와 같은 시간대를 쓰지 않으면 금요일
야간작업의 부적합이 다음 주로 밀린다. 월요일이 아닌 날짜와 아직 오지 않은 주는 거부한다.

**수집 항목:** 그 주에 발생한 점검 부적합(조치대기·조치완료 모두)과, 기한이 그 주까지인데
완료되지 않은 **승인된** 평가의 감소대책. 작성 중인 평가의 대책은 아직 이행 의무가 아니므로
제외한다. 안전사고는 등록 기능을 만든 뒤 연결한다 (`source_type` 에 자리는 있다).

- **수집은 여러 번 한다.** 작성 중인 회의는 [다시 수집]으로 주 중간에 생긴 항목을 덧붙일 수
  있고, 이미 적은 확인·비고는 보존된다(`UNIQUE(meeting_id, source_type, source_id)`).
  완료된 회의에는 더 붙이지 않는다 — 회의가 끝난 뒤 생긴 건은 다음 주의 몫이다.
- **완료 조건은 참석자 1명 이상뿐이다.** 논의 내용은 비워도 된다. 확인 위주로 수 분 내에
  끝나야 매주 돌아가고, 필수 서술을 강요하면 형식적인 한 줄만 남는다. 미확인 항목이 있어도
  막지 않고 몇 건인지 보여준다.
- 완료한 회의는 수정할 수 없다. 다음 주 회의에서 이어 다룬다.
- **회의 체크만으로 원본 부적합이나 평가 대책을 자동 종결하지 않는다.** 확인 여부는 회의의
  장부이고 종결은 각 처리 화면의 몫이다.
- **미실시 주 메일 알림**: 주가 끝났는데 회의 기록이 없으면 관리감독자·안전관리자에게 한 번
  보낸다. 주당 한 번이고 회사당 한 통에 밀린 주를 나열한다. 작업자에게는 보내지 않는다 —
  회의를 실시할 책임이 없는 사람에게 알리면 자기가 할 수 없는 일을 통보받는 셈이다.
  목록에서는 미실시 주에 "미실시 알림 발송 <날짜>" 가 붙는다. 호스트 cron 이 배치를 돈다
  ([notifications.md](notifications.md), [docker.md](docker.md) §4).
- 월별 발굴·조치 집계는 목록 위에 한 줄로 얹는다 — 신규 월간 메뉴를 만들지 않는다.
- 새 월간 평가 승인 절차나 신규 월간 메뉴를 추가하지 않는다.

### I-04. 점검 모니터링(유료)

**구현:** `/monitoring`. 사이드바 안전점검 하위에 '점검 기록'·'주간 안전점검 회의'와 나란히.

**배치:** 날짜·장소 필터 → 요약 3칸(TBM 미확인 / 작업 중 점검 없는 작업 / 미조치 부적합)
→ 그 날 도는 작업 목록 → 지시서·회차 상세 링크.

**점검 기록(I-01)과 보는 방향이 반대다.** 기록은 지나간 것을 기간으로 조회하고, 모니터링은
**오늘 지금 무엇이 빠졌는가**를 본다. 그래서 기간이 아니라 날짜 하나를 고르고, 회차가 아니라
"그 날 도는 작업"을 행으로 놓는다. 미이행 작업은 왼쪽 테두리를 브랜드색으로 세우고 이행
완료는 조용히 둔다 — 이 화면은 빠진 것을 찾는 용도다.

- 첫 화면은 현재 누락을 찾는 데 집중한다. 추이 그래프·재해율 통계는 넣지 않았다. 답해야 하는
  질문은 "누가 아직 TBM 을 안 찍었나" 하나다. 미확인자는 **이름으로** 표시한다.
- **미조치 부적합만 전체 기간을 센다.** 조치는 작업일과 무관하게 남으므로 날짜로 걸러 버리면
  밀린 것이 화면에서 사라진다. 지난 날짜를 봐도 이 숫자는 그대로다.
- PTW 가 필요한데 승인되지 않은 작업은 함께 표시한다. 점검을 막지는 않는다.
- **무료 회사에는 행을 주지 않는다.** 다만 안내 화면에 "홈과 지시서 상세의 회차 상태는 그대로
  보입니다" 를 명시한다. 이 메뉴는 흩어진 것을 모아 주는 기능이고, 기존에 보던 것을 가져가지
  않는다.
- 장소 옵션은 최근 30일 안에 회차가 있던 작업의 장소에서 모은다. 쓰지 않는 장소가 목록을
  채우지 않게 한다.

## 10. 모바일 현장 화면

### M-00. 링크로 들어온 작업자 (`/w`)

**전제:** 로그인하지 않은 상태로 토큰 링크를 열었다. 세션이 없으므로 **목록이라는 개념이
없다** — 이 화면은 토큰이 가리키는 **작업지시 하나**만 보여준다. M-01·M-02 는 로그인 화면이다.

**배치:** 이름 인사 → 작업명·회차 시간 → 취소·PTW·회차 상태 안내 → (TBM이면) 위험요인·대책과
접어 둔 판단 기준 → 체크리스트 → 저장.

- TBM을 이미 확인했으면 작업 중 점검으로, 아니면 TBM으로 기본 진입하고 서로 오가는 링크를 둔다.
- 저장 후에는 로그인 화면으로 보내지 않고 이 화면으로 되돌린다.
- 링크가 죽었으면(폐기·만료·재발급·지시서 취소·퇴사) `/w/expired` 로 보낸다.
- 하단에 "이 링크는 본인 전용" 고지를 둔다.

### M-01. 내 작업·현장 작업 목록

**배치:** 오늘 날짜 → 작업 카드 → 계정/메뉴 하단 탐색.

**카드:** 작업명, 장소, 시간, PTW 미승인 등 주의 상태, 내 TBM 확인 여부, [작업 보기].

- 작업자는 본인 배정 작업만. 관리자는 같은 회사의 허용된 점검 대상 작업.
- 작업이 없으면 ‘배정된 작업이 없습니다’와 소속 회사 확인 안내.
- QR 스캔 전용 메뉴를 필수로 만들지 않는다. 휴대폰 기본 카메라로 QR을 열 수 있다.

### M-02. 작업 상세·점검 선택

**배치:** 작업명·장소·오늘 회차 요약 → 오늘/지난/미래 회차 목록 → 회차별 [TBM 확인하기] [작업 중 점검하기] 큰 버튼.

- PTW 미승인은 버튼 가까이에 표시한다. 설계에 없는 추가 차단은 하지 않는다.
- 목록 정렬: 오늘 회차 상단 강조, 지난 회차는 최근순으로, 미래 회차는 하단(잠금).
- 미래 회차만 잠금. 오늘·지난은 모두 입력 가능하다(작업일자 KST 기준). 지난 회차 뒤늦은 입력도 `submitted_at`이 그대로 남는다.
- 취소된 지시서는 취소 표시, 점검 입력 차단.
- 야간작업은 자정을 넘어도 시작일 기준 한 회차로 유지.

### M-03. TBM

**세로 순서:** 평가 스냅샷의 위험요인·대책 → 이전 회차 조치 내용(있을 때 팝업) → 항목별 적합/부적합/해당없음 → 코멘트·선택 사진 → 확인 체크 → 저장.

- 위험요인마다 **위험성 수준(상·중·하)과 허용 가능 여부**를 함께 표시한다.
- 그 수준의 **판단 기준은 접어 둔 안내**로 둔다(버튼을 눌러야 펼쳐진다). 기준 원문이 길어
  펼쳐 두면 체크리스트가 밀리고, 매번 읽을 내용도 아니다.
- **PTW 미승인 상태를 표시한다.** 표시만 하고 점검을 막지 않는다.
- 부적합 선택 시 알림 대상 관리자 선택.
- 사진 추가는 유료, 사진 없이도 기본 입력 가능. **항목마다** 버튼을 두고 결과에 관계없이 붙인다.
  링크로 들어온 작업자도 유료 회사면 첨부할 수 있다. 역할은 첨부 권한을 가르지 않는다.
- 고른 사진은 저장 버튼을 누를 때 함께 올라간다. 업로드 중에도 점검 기록은 이미 저장된 상태이므로,
  사진이 실패해도 기록이 날아가지 않는다.
- 손글씨 서명 화면 없음. 저장 시각과 진입 경로가 기록된다.
- 저장 후 ‘확인 완료’와 내 작업으로 이동. 다른 작업자의 미확인을 본인 완료 실패처럼 표시하지 않는다.

### M-04. 작업 중 점검

**배치:** 작업·회차 요약 → 작업 중 체크리스트 → 항목별 코멘트·선택 사진 → 저장.

- 배정 작업자·관리자 입력 가능, 횟수 제한 없음.
- TBM 미확인이어도 입력 가능. TBM 미확인은 별도로 남긴다.
- 부적합은 TBM과 같은 관리자 선택·조치 흐름으로 연결.
- 무료는 현장 입력과 저장 결과 확인까지 제공하며 과거 점검 기록 관리 화면은 유료 정책 적용.

## 11. 안전사고

### A-02. 사고 목록

**배치:** 제목＋[사고 등록] → 기간·장소·작업명 필터 → 목록.

**열:** 발생일시, 장소, 사고내용 요약, 연결 지시서, 등록자, 상세보기.

**범위:** 확정된 사고 기록 관리만 제공. 산재 조사표 자동 제출·법정 보고 완료 처리는 포함하지 않는다.

### A-03. 사고 작성·상세

**배치:** 지시서 연계 선택(선택 사항) → 일자·시간·장소·상세장소 → 사고내용 → 사진(유료) → 재발방지대책 → 저장.

- 지시서의 [사고발생]으로 진입하면 관련 정보를 스냅샷 복사.
- 복사한 정보는 사고 화면에서 수정 가능, 원 지시서에 영향 없음.
- 지시서 변경·취소 후에도 사고 기록 유지.
- 등록·열람 권한과 장소 마스터가 없는 경우 처리 방식은 원 설계상 확인 필요.

## 12. 회사정보

### C-01. 인원관리

**배치:** 현재 인원·무료 한도·요금제 → [작업자·관리자 초대] → 재직 / 가입 승인대기 / 퇴사 탭 → 인원 목록.

**목록 열:** 이름, 역할, 연락처, 가입일·퇴사일, 상태, 상세.

**초대 패널:** 이메일 또는 전화번호, 초대 경로 안내, 발송. 무료 문자 제한과 전화번호 초대의 관계는 확인사항.

**상세 패널:** 연락처, 자격증 이름·첨부, 역할, 소속 이력, 퇴사 처리.

- 자격증은 참고용. 미등록을 이유로 작업 배정을 막지 않는다.
- 직접 가입 승인·거절은 승인대기 탭에서 처리. 초대 링크 가입은 승인 생략.
- 관리감독자 승격·본인 역할 변경은 원 설계 규칙 유지.
- 마지막 관리감독자 역할 변경·퇴사 차단 사유를 즉시 안내.
- 유료 회사가 계약 구간의 인원을 다 쓰면 등록을 막고 상향 경로를 안내한다. 무료 회사에는 인원 관련 안내가 없다.
- 퇴사 시 배정 해제·과거 기록 보존을 안내한다.

### C-02. 장소관리

**배치:** 좌측 장소 트리 35% / 우측 선택 장소 정보 65%.

**동작:** 장소 등록·수정, 하위 장소 추가, 최대 5단계 계층 확인. 삭제·이동 등 미정 작업은 확정 전 제공하지 않는다.

- 선택은 최하위뿐 아니라 중간 단계도 가능.
- 지시서 작성 중 직접입력한 장소는 자동 마스터 등록하지 않는다.
- 빈 화면은 ‘장소를 등록하면 다음 작업에서 선택할 수 있습니다’＋[장소 추가].

## 13. 이용·관리

### B-01. 요금제·결제

**배치:** 현재 요금제·인원·계약 구간 → 무료/유료 비교 → 구간표·업그레이드 → 결제수단·결제 상태.

- 인원 구간별 월 정액(Basic ~19인 / Standard ~49인 / Pro ~99인, 100인 이상 개별 협의)과
  정가·출시 할인가를 함께 설명. 구간 이름은 이 화면에서만 쓰고, 기능 안내에는 "유료"라고 쓴다.
- 세 구간의 기능은 같다는 점을 명시. 구간은 가격만 가른다.
- 상향은 즉시 정산 후 그날이 새 결제 기준일, 하향은 다음 주기부터·환불 없음.
- 카드 자동결제, 연간 선납 계좌이체 안내, 100인 이상 문의.
- 실패 시 재시도 상태·결제수단 변경, 최종 실패 후 무료 전환·기록 유지 안내.
- 부가세·재시도 주기·최소 과금 등 미정 정책은 구현 전에 확정.
- 청구 증빙 종류·발행 처리는 실제 결제수단별 정책 확정 후 반영.

### B-02. 과금 내역

**배치:** 결제 주기 목록 → 주기별 청구 금액·구간 → 증빙 다운로드.

**열:** 결제일, 계약 구간, 그 주기의 인원, 공급가, 부가세, 청구액, 증빙.

- 정액제라 일자별 인원표가 필요 없다. 금액이 달라지는 사건은 **구간 상향**뿐이므로
  상향이 있던 주기에만 크레딧 차감·즉시 결제 내역을 함께 보여준다.
- 결제(PG) 도입 시 함께 만든다. 현재는 문의 폼으로 연결된다.
- 확정 스냅샷은 이후 인원 수정으로 바뀌지 않는다.

### B-03. 감사 로그

**배치:** 기간·행위자·대상 종류·행위 필터 → 로그 목록 → 상세 비교 패널.

**열:** 일시, 행위자, 대상 문서, 생성·수정·삭제·승인 구분, 접속 경로.

- 상세: 변경 전/후, 관련 문서 링크, 자가 승인 표시.
- 자기 회사 관리자만 조회. 읽기 전용, 로그 삭제 버튼 없음.
- 유료 제한 문서의 내용을 로그로 우회 조회하는 범위는 확인사항으로 둔다.

### B-04. 내 정보·본인 퇴사

**배치:** 로그인 계정 정보 → 소속·역할 → 연락처 → 본인 퇴사·로그아웃.

- 회사 변경은 본인 퇴사 후 새 회사 가입. 멀티회사 전환 메뉴 없음.
- 퇴사 후 이전 회사 기록은 회사에 남고 본인 소속은 해제됨을 안내.
- 마지막 관리감독자는 퇴사 불가 안내와 다른 관리감독자 지정 경로 제공.

### B-05. 회사 탈퇴

**배치:** 보관·삭제 안내 → [전체 기록 다운로드] → 확인 → 탈퇴.

- 원 설계의 법정 보존 기록 예외와 개인정보 처리 안내를 반영한다.
- 회사 탈퇴 실행 권한과 보관·삭제 세부 정책은 출시 전 확정.
- 개인 퇴사와 회사 전체 탈퇴를 동일 버튼으로 처리하지 않는다.

## 14. SMBE 운영자 백오피스

회사 내 관리자 메뉴와 분리된 운영자 전용 영역.

| 화면 | 기능 | 배치 |
|---|---|---|
| O-01 회사 목록 | 회사명·업종·인원·요금제·가입일 검색 | 필터＋표＋회사 상세 링크 |
| O-02 회사 상세·요금 조건 | 회사별 무료 한도, 100인 이상 개별 조건 설정 | 회사 개요 → 적용 조건 → 변경 입력·저장 |
| O-03 청구·결제 확인 | 회사별 요금제 상태·월별 청구 내역 확인 | 회사·월 필터 → 청구 목록 → 일별 근거 |

- 회사 전체 업무 문서를 무제한 열람하거나 사용자를 대신해 승인하는 기능은 설계에 없으므로 추가하지 않는다.
- 무료 한도 기본값 10명을 회사별 설정값으로 다룬다.
- 공개 안내·진단 콘텐츠는 운영자가 공식 출처·적용일·검토일·규칙 버전을 관리한다. 초기에는 파일 기반으로 검토·배포할 수 있으며 별도 CMS 화면은 필수가 아니다.

## 15. 첫 1시간 경험과 메뉴 연결

| 단계 | 화면 | 사용자가 얻는 결과 |
|---|---|---|
| 공개 유입(선택) | U-01~U-04 | 법률 안내·자가진단 결과와 다음 행동 확인 |
| 로그인·회사 생성 | A-01 / U-05 | 진단 맥락을 유지하며 내 회사 공간 생성 |
| 인원 초대 | H-01 → C-01 패널 | 실제 작업자가 참여할 경로 확보 |
| 작업 시작 | H-01 → W-02 | 표준서 없이도 업종 템플릿으로 시작 |
| 평가 확인 | W-02 안 R-02 | 위험요인·대책·참여자를 포함한 평가 기록 |
| 일정·배정·허가 | W-02 → 필요 시 P-02 | 지시서 발급 또는 승인대기 |
| 전달·출력 | W-05 | 링크와 QR 포함 지시서 |
| 현장 확인 | M-02 → M-03 | 작업자 본인의 TBM 확인 기록 |
| 결과 확인 | W-03 / I-01 | 누구에게 지시했고 누가 확인했는지 확인 |

- 작업자 가입과 타인 승인은 외부 대기 요인이다. 대기 상태를 성공처럼 표시하지 않는다.
- 본인 PTW 신청&승인은 기존 설계대로 지원한다.
- 간이평가 승인 동작은 첫 사용 성패에 영향을 주므로 구현 전에 결정한다.
- 오래된 종이 평가를 옮기는 단계는 없다.
- 다음 날은 W-01 또는 홈의 복사 버튼으로 반복한다.

## 16. 이번 범위에서 만들지 않는 메뉴

원 설계 16장의 향후 확장을 보존한다. 현재 메뉴에 빈 페이지로 나열하지 않는다.

| 후속 묶음 | 메뉴 후보 |
|---|---|
| 교육·법정 일정 | 안전보건교육, 건강진단 등 일정, 법정 캘린더 |
| 제보·확장 개선조치 | 아차사고·안전제보, 모든 경로의 통합 개선조치 |
| 대외 보고 | 산업재해 조사표·중대재해 보고, 문서함·서식 모음 |
| 전문 업무 | 도급·협력업체, 보호구, 기계·안전검사, MSDS, 측정·건강진단, 비상훈련, 법정 선임 |
| 추가 운영 | 공지사항·통합 알림함, 고객지원, 장기 통계 |

## 17. 원 설계에서 추가 결정이 필요한 UI 경계

아래는 새 기능을 늘리자는 제안이 아니라, 구현 시 임의로 정책을 정하지 않기 위한 목록이다.

| 항목 | 현재 근거·빈틈 | 결정할 내용 |
|---|---|---|
| 평가 승인 | 승인된 평가만 지시서 사용, 간이평가도 공통 규칙 | 관리자 작성 시 직접 승인 가능 여부, 저장·승인 버튼, 승인자 지정 방식 |
| 평가·회의·사고 권한 | 역할표에 상세 권한 누락 | 작업자 작성·열람 범위, 승인·수정·조치 담당 범위 |
| 모바일 안전점수 | 무료 전체 제공과 무료 모바일 현장 기능 제한 공존 | 계정/홈에서 점수 상세까지 허용할지 |
| 무료 과거 부적합 | 1주일 점검 열람 제한, 미조치 유지 | 오래된 OPEN 항목 조회·종결 및 원 점검 표시 범위 |
| 주간 회의 과거 원문 | 회의에 부적합·사고 자동 수집 | 무료의 과거 점검 제한을 회의 상세에 어떻게 적용할지 |
| 감사 로그 | 변경 전/후 기록, 과거 문서 열람 제한 | 조회 제한 문서의 내용 노출 범위 |
| 초대 전달 | 전화번호 또는 이메일 입력, 무료 알림은 메일만 | 무료 전화번호 초대 시 링크 전달 방법 |
| 평가 회차 중첩 | 기간 자동 매칭＋단일 회차 ID | 겹치는 기간 처리 우선순위 또는 중첩 제한 |
| PTW 입력 | 필요로 올릴 때 추가 입력 없음, PTW 항목 존재 | 기존 입력 재사용 범위와 최초 허가 정보의 필수값 |
| PTW 여러 날 승인 기한 | 작업 당일까지 승인, 기간 작업 허용 | 승인 가능 마지막 날을 작업 시작일 등 어떤 날짜로 판정할지 |
| 사고 장소 | 공통 장소 선택, 일반 온보딩은 장소 미설정 허용 | 사고 화면에서 직접입력 허용 여부 |
| 첨부파일 티어 | 사진은 유료, 자격증·평가 정보 첨부 존재 | 일반 파일과 사진 용도별 제한 |
| 안전점수 입력 | 안전방침·교육 이수 등을 산정 근거로 사용 | 기존 입력 경로·최종 산식·게이지 표현 |
| 회사 탈퇴 | 전체 다운로드 후 탈퇴 | 실행 역할과 다운로드 범위·보관 정책 |
| 요금 세부 | 일할·후불·자동 유료 확정, 일부 세부 미정 | 부가세·결제 실패·증빙 처리·전환 고지 |

| 공개 콘텐츠 | 가이드·준비도 진단은 확정, 해설·문항 원문은 미작성 | 공식 최신 대상 조건·혜택·최종 문항과 규칙 검토 후 게시 |

## 18. 화면 검토 기준

- 로그인 이후 인원 초대와 작업지시 시작이 홈에서 즉시 보이는가?
- 표준서·장소가 없어도 간이평가와 직접입력으로 진행되는가?
- 작업지시 작성 도중 다른 문서를 만들고 원래 작성 내용으로 돌아오는가?
- 작업표준서와 위험성평가가 별개임이 메뉴와 상세에서 명확한가?
- 작업자는 링크를 열고 자기 작업을 바로 확인하는가?
- 무료 사용자에게 현재 현장 기능과 유료 기능의 경계가 명확한가?
- 작업기간 종료, PTW 승인, TBM 확인, 부적합 조치가 서로 다른 상태로 보이는가?
- 반복 작업은 복사 후 필요한 값만 확인해 발급하는가?
- 승인·발급 실패와 대기 상태를 정확하게 보여주는가?
- 원 설계에 없는 다단계 승인·이관 의무·추가 메뉴가 끼어들지 않았는가?

- 공개 가이드·진단·결과를 로그인 없이 PC·모바일에서 확인할 수 있는가?
- 공개 문서의 적용 기준일·검토일·공식 출처가 표시되고 시행 예정 내용과 구분되는가?
- 공개 진단과 실제 위험성평가 작성·공단 인정을 혼동하지 않는가?
- 기존 종이·엑셀 기록도 응답에 반영하며 SMBE 미사용을 미실시로 판정하지 않는가?
- 가입 후 응답과 선택 행동을 이어가되 실제 업무 기록이나 과금 인원을 자동 생성하지 않는가?
- 공개 페이지 본문은 검색 가능하고 개인 진단 결과·응답은 검색에 노출되지 않는가?
